## T3 — OPC UA resource counters (implementation in progress)

The `service` and `admin` roles now have a read-only
`Device.Diagnostics.OpcUa` subtree. The four server-lifecycle gauges
`Sessions`, `SecureChannels`, `Subscriptions` and `MonitoredItems` each expose
`Current`, `Peak` and `Capacity` as UInt64 object counts. Their currents and
peaks are updated at open62541 create/delete notifications (the monitored-item
register callback for monitored items); configured capacities remain the
production limits of 4, 4, 4 and 128. Peaks reset on server rebuild. The
provider uses fixed storage and short FreeRTOS critical sections; its
boot-lifetime counter pairs use modulo-2^64 values and saturating wrap counts.
The same one-second snapshot cadence as T2 publishes the values. Missing
snapshots return `BadNoData`; unavailable measurements return
`BadNotSupported` without a numeric value. `viewer`, `operator` and anonymous
sessions cannot Browse this subtree and direct Reads return
`BadUserAccessDenied`.

The additive NodeIds are
`Device.Diagnostics.OpcUa.<Sessions|SecureChannels|Subscriptions|MonitoredItems|PublishRequests|EventQueue>.<Current|Peak|Capacity>`
and `Device.Diagnostics.OpcUa.<RejectedRequests|RejectedRequestsWrapCount|EventQueueDrops|EventQueueDropsWrapCount>`.
`PublishRequests.Current` and `.Peak` are exact server-owned counts updated
on every response-queue enqueue/dequeue, including cancellation; Capacity is
`maxSessions * maxPublishReqPerSession` (16 in the production profile).
`EventQueue.Current` and `.Peak` count retained event notifications in
client MonitoredItem queues, including overflow markers, at the actual
queue mutations. Its `Capacity` is a dynamic sum of negotiated physical
per-item bounds `2 * queueSize + 1`. It is a bound, not preallocated memory;
deleting an item can make current Capacity smaller than the historical Peak.
The queue is bounded by the existing maximum 128 monitored items and 1..8
negotiated normal queue entries per item. The server-owned
`EventQueueDrops` pair counts actual non-marker event notifications deleted
by the per-item overflow path, not the built-in overflow-marker count.
`RejectedRequests` is defined precisely as successfully transmitted
`ServiceFault` responses. It excludes bad per-operation result arrays and
transport-handshake failures; the name must not be interpreted as every
rejected field operation. Both counter pairs retain boot-lifetime totals
across controlled server rebuilds and mark `BadNoData` if an owner snapshot
gap makes a total unknowable.

## T4 — reproducible firmware profiles

T4 adds compile-selected, test-only synthetic workloads without adding a
persisted preset/driver ID, configuration field or public OPC UA node. The
existing `dev_benchmark` preset remains the physical-input preset. The frozen
matrix consists of 1/4/8/16 synthetic channels, 1/10 Hz periods, declared
1/2/4-client external load, Events off/on, history off/on, FULL Namespace 0,

Benchmark images bypass persisted configuration recovery and reject runtime
configuration mutations, so Flash state cannot replace or alter the declared
workload. Events-off disables native alarm evaluation and OPC UA custom Event,

the existing historized channel flag. The secure axis exposes only the
Basic256Sha256/SignAndEncrypt endpoint, including on a commissioning-state
device; `test-none` is rejected outside an explicit benchmark build and keeps
the normal username authentication and role authorization callbacks.
Production defaults and resource capacities are unchanged.

Deterministic `benchmark_profile.json`, generated `config_export.json`, and a
bounded host verifier record/check exact profile settings. The CMake selector
rejects invalid axis values, industrial/network-only/bootloader/legacy
combinations and any attempt to select `test-none` for a normal image.
