# v0.3.2 implementation report

## Status

The v0.3.2 Maintenance Workflow Core implementation is complete in the current
working tree and the reference Debug firmware build succeeds.

The release is not yet fully accepted because target runtime verification,
UaExpert verification, and adapter-level failure injection for the public
open62541 event API have not been performed.

## Implemented scope

- Added the bounded, volatile, open62541-independent `maintenance_service`.
- Implemented `PlanMaintenance`, `RescheduleMaintenance`,
  `StartMaintenance`, and `FinishMaintenance`.
- Implemented only the AMB transitions:
  - `Finished -> Planned`;
  - `Planned -> Executing`;
  - `Executing -> Finished`.
- Kept rescheduling within `Planned` without a transition event.
- Added fixed bounds for identifiers, actor, result, supplier, personnel, and
  serviced/replaced part lists.
- Added a prepare/apply/commit transaction with:
  - inactive prepared storage;
  - one active committed snapshot;
  - one atomic active-index and revision commit point;
  - no compensating rollback after commit.
- Added service-owned event-publication fault state containing the committed
  revision and operation.
- Added OPC UA Methods with secure `service`/`admin` authorization.
- Added read-only service-backed data sources for maintenance state, AMB
  properties, and condition metadata.
- Added live transition events after successful commits.
- Defined successful return from the public open62541 event API as successful
  firmware publication.
- Preserved committed state when the public event API reports a post-commit
  failure and reject subsequent mutations with `BadResourceUnavailable`.
- Added the AMB `NameNodeIdDataType` and the supplier, qualification,
  serviced-parts, and replaced-parts fields.
- Established `0.3.2` as the single CMake firmware-version source.
- Added structural, workflow, authorization, event-cardinality, boundary, and
  native service transaction/fault-policy verification.

## Atomic publication behavior

Prepared values remain outside the active OPC UA AddressSpace. Maintenance
data-source callbacks copy only the active committed service snapshot.
Independent callbacks may observe different committed revisions, but no
callback can observe prepared or partially committed values.

Transition event fields are prepared before commit. The public open62541 event
API is called only after the service snapshot commit. A failure returned by
that API never rolls back the committed transition. Failures hidden inside the
internal open62541 subscriber fan-out are documented platform limitations and
are outside the firmware correctness boundary.

## OPC UA contracts

Methods:

| NodeId | Required role | Behavior |
| --- | --- | --- |
| `Device.Maintenance.PlanMaintenance` | `service` or `admin` | `Finished -> Planned` |
| `Device.Maintenance.RescheduleMaintenance` | `service` or `admin` | Updates `Planned` without transition |
| `Device.Maintenance.StartMaintenance` | `service` or `admin` | `Planned -> Executing` |
| `Device.Maintenance.FinishMaintenance` | `service` or `admin` | `Executing -> Finished` |

Service-backed values:

- `MaintenanceState.CurrentState`;
- `MaintenanceState.CurrentState.Id`;
- `PlannedDate`;
- `EstimatedDowntime`;
- `MaintenanceMethod`;
- `MaintenanceSupplier`;
- `QualificationOfPersonnel`;
- `PartsOfAssetReplaced`;
- `PartsOfAssetServiced`;
- `ConfigurationChanged`;
- condition `Message`, `Severity`, `Quality`, `Time`, and `ReceiveTime`.

Status mapping:

- invalid argument shape or type: `BadInvalidArgument`;
- value outside documented bounds: `BadOutOfRange`;
- forbidden source state: `BadStateNotActive`;
- insufficient role: `BadUserAccessDenied`;
- insecure session: `BadSecurityModeInsufficient`;
- busy, unavailable, or event-publication-fault state:
  `BadResourceUnavailable`;
- unexpected internal failure: `BadInternalError`.

`operator_username`, `service_username`, and `admin_username`. No device
operation ran and no device StatusCode was returned. Per the acceptance-session
stop rule, the workflow matrix was not continued and no code was changed.
