# v0.4.1 — Channel Runtime Hardening

## Contract

Baseline: tag `v0.4.0`, commit
`8a454945aaccc3d381a2e889e90b53569415b705`.

Complete the existing generic channel data plane without adding the dynamic
OPC UA channel information model scheduled for v0.4.2. Preserve every v0.4.0
public NodeId, BrowseName, Method signature, EventType, permission,
configuration field and externally visible behavior.

This release may change internal service and driver APIs. It must not add new
public OPC UA nodes, companion specifications, persistence features, alarm or
history generalization, Modbus support, computed channels, or dynamically
loaded driver code.

Use `code-mapper` before implementation. Assign service/runtime and native
driver work to `embedded-systems`, OPC UA compatibility verification to
`iot-engineer`, build/size/profile work to `build-engineer`, and the integrated
diff to `code-reviewer`. The primary agent owns API decisions, persistence
migration, integration and the release gate.

## Baseline

Treat tag `v0.4.0` as the accepted implementation and compatibility baseline.
Before measuring v0.4.1 regressions, capture the baseline artifacts and metrics
needed by the affected gate, such as public-contract inventory and binary or
memory sizes. Re-running the complete v0.4.0 release gate is not a prerequisite
for starting v0.4.1.

## Public contracts and resource effects

- Replace `CONFIG_SERVICE_MAX_CHANNELS` and
  `CHANNEL_MANAGER_MAX_CHANNELS` with one platform limit. The reference profile
  default is 16; invalid values must fail at compile time.
- Increasing the configuration array changes `device_profile_config_t` and its
  raw persisted payload. A device carrying a valid v0.4.0 four-channel payload
  must load and migrate it deterministically. Do not silently reset to defaults,
  reinterpret trailing bytes, or make an interrupted migration destroy the last
  known-good slot. External JSON field names and schema behavior remain
  compatible.
- Record before/after sizes for configuration snapshots, channel slots,
  registry state, sensor-task stack, `.data`, `.bss`, internal SRAM, PSRAM,
  ELF, UF2 and BIN. Compiled but inactive drivers must not reserve permanent
  per-channel runtime memory.
- The intended OPC UA public-contract delta is empty. Run the v0.4.0 contract
  inventory gate and explain any drift as a release blocker.

## File-level implementation plan

### T1 — Platform limit and persisted-configuration compatibility

Primary files:

- `services/include/services/config_service.h`;
- `services/include/services/channel_manager.h`;
- `services/include/services/config_wire.h`;
- `services/src/config_service.c`;
- `services/src/config_validate_service.c`;
- `services/src/config_export_service.c`;
- `services/src/config_store_service.c` and
  `services/src/config_store_limits.h`;
- `app/basic_profile/main.c` and
  `app/basic_profile/generate_config_export.cmake`;
- model consumers of the old limits under `opcua_model/src/`.

Introduce one compile-time platform channel limit and use it for configuration,
runtime storage, model context arrays, PubSub writer state and diagnostics.
Add static assertions for the supported range and Flash-slot fit.

Define a bounded compatibility representation for the v0.4.0 raw payload.
Decode it into the current in-memory profile, validate it, and write the new
representation only through the existing atomic staged/save path. Reject
unknown sizes or versions with an observable error while preserving the last
known-good configuration. Do not persist a newly resized native struct under
the old layout contract without an explicit compatibility decoder.

Tests cover empty, 1, 4, 16 and 17-channel inputs; duplicate IDs; payload-size
boundaries; old-payload load/migration; corrupt, truncated and interrupted
migration; and JSON round trips.

### T2 — Manager-owned channel state and synchronization

Primary files:

- `services/include/services/telemetry_channel.h`;
- `services/include/services/channel_manager.h`;
- `services/src/channel_manager.c`;
- `services/include/services/channel_config.h`;
- `services/src/sensor_manager.c`;
- direct consumers in `alarm_service.c`, `history_service.c` and
  `opcua_model/src/model_access.c`, `model_channels.c`, `model_history.c`,
  `model_pubsub.c` and `model_address_space.c`.

Make the registry own fixed-capacity channel slots and bounded copies of ID,
name, description and unit. Registration must never retain pointers into staged
configuration or caller stack storage. Replace `get_by_index`, `find_by_id` and
`find_by_name` raw mutable-pointer APIs with explicit operations:

- immutable metadata/runtime snapshots by ID or stable index;
- bounded iteration that does not expose internal addresses;
- validated settings/runtime updates;
- driver-operation acquisition with documented lifetime or generation checks.

Document the single writer/multiple reader rules. Critical sections may protect
only bounded slot lookup/copy/publication. Driver calls, hardware access,
history recording, callbacks and full-registry work must run outside the global
critical section. Define deterministic results for full registry, duplicate ID,
stale generation, reset during access, partial activation and failed update.

Host tests must exercise coherent snapshots during interleaved poll/read/update,
metadata lifetime after caller buffers disappear, capacity, iteration, reset
and failed activation. Where host scheduling cannot prove the FreeRTOS path,
add a target stress test with counters/invariants.

### T3 — Type-safe values and source timestamps

Primary files:

- `services/include/services/telemetry_channel.h`;
- `services/include/services/telemetry_driver.h`;
- `services/src/config_service.c` and
  `services/src/config_validate_service.c`;
- driver/sample publication code;
- affected alarm/history/model adapters.

Define a service-owned 64-bit UTC source timestamp with Unix epoch and
microsecond resolution. Specify the invalid/unknown value and conversion rules
for RTC-not-synchronized, overflow and OPC UA `DateTime`; adapters must not
replace a valid source timestamp with model-layer time.

For float, double, signed/unsigned 32/64-bit, Boolean and bounded string values,
either provide end-to-end snapshot/publication support or reject the exact
driver/type combination before activation. Numeric conversion must check range;
negative-to-unsigned, overflow and truncation are errors, not saturation or
fallback to float. String length and termination remain bounded.

Add table-driven tests for every accepted type, all rejected combinations,
numeric limits, string capacity, timestamp conversion and coherent value,
quality and timestamp snapshots.

### T4 — Driver lifecycle, hardware ownership and resource claims

Primary files:

- `services/include/services/telemetry_driver.h`;
- `services/include/services/driver_catalog.h`;
- `services/src/driver_catalog.c`;
- new native implementations and public driver headers under `drivers/`;
- `drivers/CMakeLists.txt` and `services/CMakeLists.txt`;
- profile-level driver selection in the root/app CMake integration.

Define bounded driver capabilities and lifecycle operations for applicable
drivers: `start`, `stop`, `read`, `write`, `configure` and `self_test`. Each
operation has explicit unsupported, invalid-state, timeout and hardware-failure
results. Initialization rollback must stop already-started channels in reverse
order and leave the previous running configuration active.

Move all ADC/GPIO register access, initialization state and sampling into
`drivers/`. Keep the catalog in `services/` as a hardware-independent registry
of statically compiled descriptors. Build options must allow a disabled native
driver to disappear from the ELF and `SupportedDrivers`; inactive compiled
drivers allocate no permanent per-channel state.

Add a pre-activation resource-claim pass for ADC inputs, GPIO pins and declared
shared peripherals. Claims define exclusive versus shareable use and reject
conflicts before hardware mutation. Include a bounded writable loopback driver
for host/development tests without making it part of production profiles by
default.

Tests cover lifecycle order, unsupported operations, start/configure/read/write
failures, rollback, self-test, duplicate exclusive claims, permitted shared
claims, invalid source/type pairs and build-time driver exclusion.

### T5 — Remove the active primary-temperature path

Primary files:

- `services/include/services/sensor_manager.h`;
- `services/src/sensor_manager.c`;
- `services/src/alarm_service.c`;
- `app/basic_profile/main.c`;
- temperature compatibility consumers under `opcua_model/src/`.

Make the sensor task activate and poll the configured registry without choosing
a primary channel or maintaining a second temperature snapshot. Route consumers
through channel snapshots. If the public v0.3 temperature node still requires
an adapter, isolate it behind a deprecated compatibility API that reads the
configured legacy channel and owns no independent runtime value.

Tests prove that channel ordering does not select behavior, a configuration
without temperature operates normally, the compatibility node observes the
same sample as the registry, and duplicate polling/history/alarm publication
does not occur.

### T6 — Integration, documentation and release evidence

Update `static/tools/run_host_tests.py`, focused C host suites, configuration
tools, `docs/known_limits.md`, README, changelog/release notes and schema/API
documentation affected by the final design. Version remains sourced from
`cmake/firmware_version.cmake` and must report 0.4.1 consistently only in the
implementation/release commit.

Run mixed 1, 4 and 16-channel profiles containing analog, Boolean,
signed/unsigned integer and writable loopback channels. Verify concurrent
sampling and reads return coherent value/quality/timestamp tuples. Demonstrate
that adding the mock driver requires no OPC UA model source change.

## Verification gate

Run and record:

1. `git diff --check`;
2. all host tests through `static/tools/run_host_tests.py`;
3. first-party static analysis;
4. focused configuration migration, registry concurrency, type, timestamp,
   lifecycle, resource-claim and rollback tests;
5. exact reference RP2350 Debug build;
6. driver-enabled and driver-disabled build variants required by T4;
7. config/security/OTA/history/AMB verification retained from v0.4.0;
8. `verify_opcua_public_contract.py` against tag v0.4.0 and exported
   NodeSet/public inventory comparison;
9. artifact/version checks and baseline-to-final size report;
10. automated asyncua/open62541 checks and UaExpert for affected existing nodes;
11. independent `code-reviewer` after the integrated diff is ready.

Verification scripts must exit nonzero on failure. Report hardware, network or
UaExpert checks as not run unless they were actually performed.

## Completion

Done only when:

- one bounded limit governs all channel capacity;
- v0.4.0 persisted configuration migrates without losing the known-good slot;
- registry state and metadata are owned and exposed only through safe APIs;
- concurrent sampling/read snapshots are coherent;
- every advertised type is supported or rejected before activation;
- the 64-bit timestamp contract is documented and verified;
- native hardware access resides in `drivers/` and resource conflicts are
  rejected before mutation;
- primary-temperature runtime state is removed or reduced to a stateless
  compatibility adapter;
- 1/4/16-channel, failure, rollback and resource-limit tests pass;
- public OPC UA contract drift is empty;
- build, static-analysis, size, documentation and independent-review gates pass;
- no v0.4.2 feature entered the diff.

Do not create a release tag, implement v0.4.2, or modify roadmap scope while
implementing this plan.
