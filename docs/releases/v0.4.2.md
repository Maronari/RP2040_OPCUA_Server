# v0.4.2 — Generic OPC UA Channel Information Model

## Contract

Baseline: tag `v0.4.1`, commit
`a5ebc3231faf658325ad02e997f05acf8601e8bf`.

Build the public OPC UA channel address space from the generic runtime channel
registry instead of special-casing individual signals.

Preserve all unrelated v0.4.1 public NodeIds, BrowseNames, Method signatures,
EventTypes, permissions, configuration fields and externally visible behavior.
The legacy temperature NodeId remains available for the deprecation period and
must observe the same registry-backed value, quality and source timestamp as its
generic channel representation.

This release may extend internal service and OPC UA adapter APIs where required
to expose stable channel metadata and writable-channel operations. It must not
implement the multi-channel history/alarm generalization scheduled for v0.4.3,
transactional live channel-model regeneration scheduled for v0.5.0, new
persistence schemas, Modbus support, computed channels, dynamically loaded
driver code, or unrelated model refactoring.

Use `code-mapper` before implementation. Assign service/runtime API work to
`embedded-systems`, OPC UA model and interoperability work to `iot-engineer`,
build/version/resource evidence to `build-engineer`, and the integrated diff to
`code-reviewer`. The primary agent owns NodeId policy, service/model contracts,
integration and the release gate.

Before implementation, repository instructions must identify v0.4.2 as the
current release. If `AGENTS.md`, `ROADMAP.md` and this plan disagree, stop before
editing.

## Baseline

Treat tag `v0.4.1` as the accepted implementation and compatibility baseline.

The v0.4.1 channel registry is the authoritative runtime data plane. v0.4.2
reflects that data plane into OPC UA; it must not introduce a second channel
state owner.

Capture the v0.4.1 public-contract inventory and resource metrics required for
comparison before measuring v0.4.2 regressions.

## Architecture and public-contract rules

Services own channel metadata, runtime state, synchronization and driver
operations. OPC UA callbacks remain adapters: they validate and convert OPC UA
values, call service APIs and map service results to deterministic OPC UA
StatusCodes.

Drivers own hardware and device-specific write/read behavior.

The OPC UA layer must not:

- retain mutable pointers into the channel registry;
- cast or interpret `driver_context`;
- call driver `write` operations directly;
- infer driver/source identity from pointer values or registry order;
- maintain an independent copy of channel runtime values;
- regenerate valid source timestamps using model/server time.

The model topology is created from the running channel registry during OPC UA
server startup.

v0.4.2 does not require safe live node deletion/recreation when configuration
topology changes. Structural channel changes may use the existing controlled
restart/reboot behavior. Transactional live model regeneration belongs to
v0.5.0.

Public channel NodeIds must be deterministic functions of validated channel IDs.
They must not depend on:

- registry index;
- registration order;
- memory addresses;
- boot time;
- runtime generation;
- driver implementation pointers.

Use one stable hierarchy below the existing Device model. The intended shape is
conceptually:

- `Device.Channels`;
- `Device.Channels.<channel-id>`;
- `Device.Channels.<channel-id>.Value`;
- fixed metadata children below each channel object.

The implementation plan must freeze the exact NodeId grammar before model code
is written. If valid channel IDs can collide with separators, reserved suffixes
or other generated identifiers, define one reversible and bounded encoding rule
and verify it with automated tests.

### T2 — Stable channel source metadata

Primary files:

- `services/include/services/telemetry_channel.h`;
- `services/include/services/channel_manager.h`;
- `services/include/services/config_service.h`;
- `services/include/services/driver_catalog.h`;
- `services/src/channel_manager.c`;
- `services/src/sensor_manager.c`.

The running channel API must expose enough stable information for the OPC UA
model to report the configured driver/source identity without reaching through
opaque driver state.

Expose stable source metadata through a service-owned immutable descriptor or
snapshot. It must provide the identifiers required by the roadmap, including the
stable `driver_id` and source identity used by configuration.

Do not expose source information by:

- casting `driver_context`;
- exporting driver-private structs;
- comparing driver vtable addresses;
- relying on registry index.

Any added strings, descriptors or copies must remain bounded and have explicit
ownership.

Tests cover descriptor lifetime, all configured native driver/source
combinations, invalid source identifiers, registry reset/rebuild and snapshot
coherency.

### T3 — Service-owned writable channel operation

Primary files:

- `services/include/services/channel_manager.h`;
- `services/include/services/telemetry_channel.h`;
- `services/include/services/telemetry_driver.h`;
- `services/src/channel_manager.c`;
- affected driver tests.

Add a bounded service-level channel value write operation or equivalent API.

The OPC UA layer must not invoke `telemetry_driver_vtbl_t::write` directly.

The service operation must:

1. resolve the channel using a stable identifier;
2. reject missing or disabled channels;
3. reject channels without writable capability;
4. validate exact channel value type;
5. acquire a generation/lifecycle-safe driver operation;
6. call the driver outside the registry/global critical section;
7. validate that the operation still applies to the active generation;
8. publish the resulting runtime state consistently;
9. return a service-owned result enum independent of open62541.

Define deterministic results for:

- channel not found;
- read-only channel;
- disabled channel;
- invalid value type;
- unsupported driver write;
- stale generation;
- invalid lifecycle state;
- driver timeout;
- hardware failure;
- resource failure.

Do not silently coerce unsupported values to `float`.

Tests cover successful writes, read-only rejection, type mismatch, unsupported
write, driver failure, stale handles/generations, concurrent registry changes
and coherent post-write snapshots.

### T4 — Generic OPC UA channel builder

Primary files:

- `opcua_model/src/model_channels.c`;
- `opcua_model/src/model_address_space.c`;
- `opcua_model/src/opcua_model_internal.h`;
- `opcua_model/src/opcua_model_context.c` if bounded model-owned channel state is
  required.

Create one OPC UA channel object for every configured runtime channel available
at server startup.

Implement one generic channel construction path driven by immutable registry
snapshots.

Do not add channel-specific creation functions for:

- temperature;
- ADC;
- GPIO;
- Boolean channels;
- counters;
- individual native drivers.

Each channel object exposes at minimum:

- typed `Value`;
- description;
- engineering unit;
- engineering range when configured;
- channel kind;
- stable driver/source identifier;
- sample period;
- publish period;
- historizing state;
- writable capability.

Use OPC UA standard types such as `EUInformation` and `Range` where
appropriate instead of vendor-formatted strings.

All generated BrowseNames, NodeIds, qualified names and temporary strings must
have explicit maximum sizes.

Model callback contexts may retain:

- stable channel IDs;
- bounded immutable metadata copies;
- explicit model-owned indexes only where their lifetime is guaranteed.

They must not retain pointers into mutable registry slots.

### T5 — Deterministic model-build failure behavior

Primary files:

- `opcua_model/src/model_channels.c`;
- `opcua_model/src/model_address_space.c`;
- `opcua_model/src/opcua_model_core_lifecycle.c`;
- model context ownership helpers.

Channel address-space creation must remain bounded for
`PLATFORM_CHANNEL_LIMIT`.

Define deterministic behavior for failures after any partially created channel
object or child node.

On failure:

- release temporary allocations;
- delete or invalidate nodes created by the failed channel-model transaction;
- do not expose the OPC UA model as successfully initialized;
- do not leave callback contexts referencing discarded registry/model state;
- preserve unrelated address-space state according to the existing server
  startup contract.

Do not rely on process reboot as the only cleanup mechanism for ordinary
allocation or node-creation failure.

Add focused failure-injection or host-level tests for failures at multiple
creation stages.

### T6 — Typed `Value`, quality and source timestamp

Primary files:

- `opcua_model/src/model_channels.c`;
- `opcua_model/src/model_common.c` if generic conversion helpers belong there;
- service/model conversion tests.

Support all value types accepted by the v0.4.1 channel runtime:

- `Float`;
- `Double`;
- `Int32`;
- `UInt32`;
- `Int64`;
- `UInt64`;
- `Boolean`;
- bounded `String`.

One read operation must obtain one coherent channel snapshot and use that same
snapshot for:

- value;
- quality;
- source timestamp.

Map `service_quality_t` deterministically to an OPC UA `StatusCode`.

Convert the service-owned Unix-microsecond source timestamp to `UA_DateTime`.
If the service timestamp is valid, do not replace it with model/server time.

Define behavior for the service's invalid/unknown timestamp representation.

Do not:

- regenerate source timestamps at read time;
- truncate 64-bit values;
- convert integer channels through floating point;
- silently saturate out-of-range values;
- expose unsupported values under the wrong OPC UA built-in type.

Add table-driven tests for every supported type, numeric boundaries, maximum
string length, invalid timestamp and every quality mapping.

### T7 — Writable OPC UA channel values and authorization

Primary files:

- `opcua_model/src/model_channels.c`;
- `opcua_model/src/model_access.c`;
- affected security/access verification.

A generic channel `Value` node is writable only when the underlying channel
declares writable capability and the current user/session satisfies the
existing role policy.

OPC UA write callbacks must:

1. enforce existing session/role authorization;
2. validate the supplied OPC UA built-in type;
3. perform exact bounded conversion to `telemetry_channel_value_t`;
4. reject overflow, truncation and incompatible types;
5. call the service-level write API from T3;
6. map the service result to a deterministic OPC UA StatusCode.

Do not expose writable access merely because a driver vtable contains a
non-null `write` function. Public writable capability comes from the validated
runtime channel contract.

Tests cover:

- anonymous/unauthorized writes;
- authorized writes;
- read-only channels;
- wrong OPC UA data types;
- numeric overflow;
- maximum string length;
- driver failure;
- stale/reconfigured channel.

### T8 — Legacy temperature compatibility

Primary files:

- legacy temperature handling in `model_channels.c`;
- `model_address_space.c`;
- related access/history compatibility adapters;
- public-contract verification.

Keep the established legacy temperature NodeId available for the documented
deprecation period.

It must be implemented as an alias, reference or stateless adapter to the same
registry-backed channel used by the generic channel model.

It must not:

- keep a second runtime value;
- maintain an independent quality value;
- generate its own source timestamp;
- poll the sensor independently;
- duplicate history recording;
- duplicate alarm state.

For the same channel sample, automated verification must prove that the legacy
temperature node and generic channel `Value` expose equivalent value,
StatusCode and source timestamp.

The v0.4.2 work must not generalize history or alarm services to arbitrary
channels. That work remains v0.4.3.

## Verification gate

### Authorized OTA target verification

Codex may upload a verified v0.4.2 test firmware artifact to the
user-designated reference device through the repository's existing
authenticated OTA workflow, finalize the staged image and reboot the device as
part of hardware verification. This authorization covers the device-state
change required by the test; it does not authorize new OTA features, bypassing
authentication or integrity checks, changing boot/rollback policy, or targeting
an unconfirmed device.

Before the upload, confirm the intended endpoint/device, reference board/profile,
artifact version and integrity. Preserve the known-good configuration unless a
test explicitly requires a documented configuration change. Record the exact
artifact, endpoint, commands, transfer/finalize/reboot outcome and post-reboot
recovery. If the endpoint, credentials or device identity cannot be confirmed,
report OTA verification as not run rather than guessing.

Run and record:

1. `git diff --check`;
2. all host tests through `static/tools/run_host_tests.py`;
3. first-party static analysis;
4. focused source-metadata and service-write tests;
5. table-driven type/quality/timestamp conversion tests;
6. generic channel-model construction and rollback/failure tests;
7. exact reference RP2350 Debug build from `AGENTS.md`;
8. no new first-party compiler warnings;
9. `verify_opcua_public_contract.py` against tag `v0.4.1`, with every intended
   public addition documented;
10. exported NodeSet/public inventory comparison against v0.4.1;
11. discovery-based generic channel-model verification;
12. automated asyncua/open62541 browse/read checks for mixed channel types;
13. automated authorization and writable/read-only channel checks;
14. legacy temperature versus generic-channel value/status/timestamp comparison;
15. reboot/reconnect NodeId stability check with unchanged configuration;
16. artifact/version integrity checks;
17. baseline-to-final memory and artifact size report;
18. UaExpert browse/read/write inspection on the target when available;
19. authenticated OTA upload of the verified test artifact to the confirmed
    reference device, followed by finalize, reboot, reconnect and firmware
    version/health checks, when the device is available;
20. independent `code-reviewer` after the integrated diff and focused checks are
    complete.

Verification scripts must exit nonzero on failure.

Report hardware, network, reboot, UaExpert and resource measurements as not run
unless they were actually performed.

## Completion

Done only when:

- every configured runtime channel present at server startup has one generic
  OPC UA channel object;
- one generic model path supports every accepted channel value type;
- no channel-specific creation function was added to model core;
- channel NodeIds are deterministic and stable across reboot with unchanged
  configuration;
- NodeIds depend on validated channel IDs rather than registry order or runtime
  addresses;
- value, quality and source timestamp are obtained from one coherent runtime
  snapshot;
- valid source timestamps are propagated rather than regenerated by the model;
- service quality maps deterministically to OPC UA StatusCode;
- standard `EUInformation` and `Range` are used where appropriate;
- stable driver/source identity is exposed through service-owned metadata;
- the OPC UA layer does not inspect opaque `driver_context`;
- writable channels use a service-level write API;
- role, type and capability checks are enforced before driver writes;
- read-only channels reject writes deterministically;
- temporary allocations and callback contexts are explicitly bounded;
- partial channel-model construction cleans up deterministically;
- the legacy temperature NodeId observes the same registry-owned state and does
  not introduce a duplicate value;
- channel-model verification discovers channels instead of assuming
  `Temperature1`;
- mixed-channel automated verification passes;
- public-contract, build, static-analysis, version, size and independent-review
  gates pass;
- no v0.4.3 multi-channel history/alarm work entered the diff;
- no v0.5.0 transactional live model-regeneration work entered the diff.

Do not create a release tag, implement v0.4.3 or later roadmap work, or modify
`ROADMAP.md` while implementing this plan.
