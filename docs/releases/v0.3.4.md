# v0.3.4 — 0.3 Stabilization and Release Integrity

## Contract

Baseline: tag `v0.3.3`, commit `19bf3d24e80e217f960b251654c323eacfcf1c0f`.

Implement this plan end-to-end in one run. Follow `AGENTS.md` and `ROADMAP.md`; do not edit them or this file. Preserve unrelated changes.

No new OPC UA features, public NodeIds/BrowseNames/Methods/events/schema changes, v0.4 work, dependency upgrades, broad refactors, or speculative cleanup. Change runtime code only to fix a reproduced defect required by this plan. Never weaken or suppress a failing gate.

Use `code-mapper` first. Then assign disjoint work:

* `build-engineer`: version, CMake, CI, analysis, artifacts, README/CHANGELOG.
* `embedded-systems`: host tests and documented limits.
* `iot-engineer`: read-only OPC UA contract comparison.
* `code-reviewer`: final read-only review.

The primary agent owns planning, integration, fixes, verification, and reporting. Do not request confirmation between stages.

## Work

### S1 — Inventory

Before editing, map:

* version sources and consumers;
* existing host/runtime tests;
* CI jobs and failure masking;
* build targets and generated artifacts;
* requested resource-limit constants and their source files;
* public OPC UA contracts versus `v0.3.3`.

Resolve subagent findings into one file-level plan.

### S2 — Documentation

Rewrite `README.md` for the actual RP2350 + PSRAM + W5500 platform: purpose, architecture, implemented capabilities, reference build, tests, artifacts, limits, and honest maturity/security status.

Add `CHANGELOG.md` with summaries and tag SHAs resolved from Git for `v0.1`, `v0.2`, `v0.3`, `v0.3.1`, `v0.3.2`, and `v0.3.3`. Add `v0.3.4` as unreleased; do not invent its SHA.

Add `docs/known_limits.md`. For channels, users, sessions, subscriptions, monitored items, history records, journal records, and OTA chunk size, record the exact value, controlling macro/configuration, source file, memory/failure behavior, and whether configurable.

### S3 — Version integrity

Keep one editable source: `cmake/firmware_version.cmake`; set it to `0.3.4`. Remove active duplicate literals, excluding historical documents.

Add a blocking verifier that checks agreement between:

* authoritative source;
* CMake project/cache;
* firmware compile definition;
* generated config export;
* OTA metadata/manifests;
* release artifacts.

On tag builds, require tag `vX.Y.Z` to equal firmware `X.Y.Z`. Every mismatch must exit nonzero.

### S4 — Host tests

Reuse/extend existing suites; avoid duplicate harnesses. Cover:

* configuration: valid/invalid staged data, bounds, unknown drivers, duplicate/invalid channels, unchanged state after rejection;
* channel registry: null/empty, duplicate, capacity, lookup, copy/update, config registration, poll failures;
* maintenance: every legal/illegal transition, bounds, atomic rejection;
* journal: codec/backend parsing, CRC, commit state, truncation, corruption, capacity/recovery;
* OTA state record: reset, finalize, validation, null, magic/version/CRC and payload corruption.

Add missing tests only. Compile C tests as C11 with `-Wall -Wextra -Werror` in temporary directories.

Add one explicit host-test runner. It must list suites deterministically, stop/return nonzero on failure, and support an injected failing test used only to prove CI failure propagation.

Audit applicable `static/tools/test_*.py` and `verify_*.py`: assertion, compiler, subprocess, connection, or missing-input failure must produce a nonzero exit.

### S5 — CI and artifacts

Replace `.github/workflows/build.yml` fake-green behavior with required blocking jobs:

1. **host** — all host tests and the injected-failure proof;
2. **firmware** — reference Debug build for `waveshare_core2350b_16mb_psram8mb`, W5500, primary OTA application;
3. **analysis** — first-party `drivers`, `services`, `opcua_model`, `ota`, `bootloader`, and `app`.

Exclude generated/vendor/open62541 amalgamation noise from first-party analysis. Remaining findings must fail CI. Remove `continue-on-error`, unconditional `|| true`, warning-only artifact handling, and non-asserting scans from required jobs.

Renode may gate only when a supported target and asserted observable behavior exist. Otherwise move it to a clearly optional manual experiment; never load RP2350 firmware into an RP2040 model as a release test.

Require and upload with `if-no-files-found: error`:

* ELF, UF2, BIN;
* section/size reports;
* generated config export;
* generated OTA/layout manifests;
* version-integrity evidence;
* static-analysis logs.

Add an artifact checker. CI must prove it fails against an empty directory and succeeds on the real build.

### S6 — Compatibility and review

Do not change public OPC UA behavior. If any `opcua_model`, NodeId, schema, Method, event, or access-control contract file changes, compare exported public inventory/NodeSet with tag `v0.3.3`; require zero externally visible drift or revert the change.

Run `code-reviewer` after integration. Fix valid findings and rerun affected gates.

## Release gate

Run and record:

1. `git diff --check`;
2. the complete host-test runner;
3. injected host-test failure proof;
4. blocking first-party static analysis;
5. the exact reference Debug build from `AGENTS.md` and its CI equivalent;
6. positive and negative artifact checks;
7. version-consistency verification;
8. all affected existing verification tools;
9. final independent review.

All commands must fail nonzero on error. Record warnings, ELF sections, SRAM/PSRAM/stack impact where measurable, and ELF/UF2/BIN sizes.

Hardware, UaExpert, and automated OPC UA runtime checks are not required when firmware/OPC UA behavior is unchanged. If such behavior changes, run all affected existing runtime, asyncua/open62541, hardware, and UaExpert checks; otherwise the change is incomplete.

## Completion

Do not edit roadmap checkboxes, create a tag, or invent a release SHA.

* artifact list;
* version evidence;
* OPC UA no-drift evidence;
* unavailable checks and residual risks;
