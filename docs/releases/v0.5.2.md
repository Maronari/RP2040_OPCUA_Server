## T2 frozen contract — Heap, PSRAM and all FreeRTOS tasks

Owner decisions recorded 2026-09-16. This section freezes behavior for the
first implementation vertical. It documents the intended change; none of the
runtime behavior or public nodes below exists yet.

### Snapshot ownership, timing and bounds

Extend the existing `diag_service`; do not create a parallel resource-metrics
service. `diag_service` owns one bounded, coherent snapshot and consumes PSRAM
and lwIP statistics through narrow provider interfaces, without hardware
access from `services/`. Use bounded double buffering and a static
synchronization object; readers never observe a partially published sample.

Collect once per second. This period is fixed for v0.5.2 and adds no
configuration field or schema migration. All child values in a sample share:

- `Device.Diagnostics.SnapshotSequence` (`UInt64`) and
  `SnapshotSequenceWrapCount` (`UInt64`);
- `Device.Diagnostics.SnapshotTimestamp` (`DateTime`), null until the wall
  clock is valid;
- `Device.Diagnostics.SnapshotAgeMs` (`UInt64`), computed from the monotonic
  clock;
- `Device.Diagnostics.TaskCount` (`UInt32`); and
- `Device.Diagnostics.TaskListTruncated` (`Boolean`) and
  `Device.Diagnostics.TaskNameConflict` (`Boolean`) and
  `Device.Diagnostics.TaskModelIncomplete` (`Boolean`).

The four task-specific root nodes (`TaskCount`, `TaskListTruncated`,
`TaskNameConflict`, `TaskModelIncomplete`) follow `enable_task_diagnostics`
and do not exist when task OPC UA diagnostics are disabled. Sequence/time/age
still describe enabled Heap/PSRAM snapshots.

Counters start when their allocator initializes, so boot/self-test activity,
task creation and OPC UA model construction are included. They reset only on
reboot. Every cumulative counter is a pair `<Name>: UInt64` plus
`<Name>WrapCount: UInt64`: the value wraps to zero after `UINT64_MAX` and its
wrap count increments. A wrap count that itself reaches `UINT64_MAX`
saturates. Gauges, minima and peaks do not wrap. All byte quantities are
`UInt64` even where retained legacy nodes remain `UInt32`.

The snapshot contains at most 16 unique task names over one boot. Task names
are compared case-sensitively after FreeRTOS truncation to
`configMAX_TASK_NAME_LEN`. FreeRTOS permits duplicates, but the exact-name
public model cannot represent two live handles under one String NodeId;
therefore unique post-truncation names are a project release invariant, not a
FreeRTOS guarantee. `uxTaskGetSystemState()` cannot
return a partial list: if the live task count exceeds 16, set
`TaskListTruncated=true`, retain the last complete task sample with
`UncertainLastUsableValue`, and do not present an arbitrary subset as the
complete list. Before the first complete sample, unavailable values are
`BadNoData`.

`TaskCount` always means the current live count returned by
`uxTaskGetNumberOfTasks()`, not the number of retained task objects. It and
`TaskListTruncated` remain current with `Good` quality when a list sample is
truncated; only the per-task values become uncertain. If no complete list has
ever been captured, count/truncation remain `Good` while per-task values are
`BadNoData`. `TaskListTruncated` also remains true if a seventeenth unique
name appears later even when the current live count falls below 16; values for
the retained known tasks may remain `Good`, but `TaskModelIncomplete` also
becomes true and the all-task acceptance gate fails. `TaskNameConflict`
becomes true when two different live handles have the same post-truncation name; such a
sample cannot create a second exact-name node, sets
`TaskModelIncomplete=true`, and retains the existing same-name object's last
values as `UncertainLastUsableValue`. It does not stop either RTOS task, but
the firmware cannot claim that all tasks are exposed and T2/release acceptance
fails until the names are unique. A live asyncua test must create two
same-name tasks and verify flags, missing second representation, quality and
recovery after the conflict disappears.

### Heap nodes and failure policy

Add the read-only folder `Device.Diagnostics.Heap`, controlled by the existing
`enable_heap_diagnostics` flag. It contains:

- `TotalBytes`, `UsedBytes`, `PeakUsedBytes`, `FreeBytes`,
  `MinimumEverFreeBytes`, `LargestFreeBlockBytes`,
  `SmallestFreeBlockBytes`, `FreeBlockCount`;
- `SuccessfulAllocations`/`SuccessfulAllocationsWrapCount`;
- `SuccessfulFrees`/`SuccessfulFreesWrapCount`;
- `FailedAllocations`/`FailedAllocationsWrapCount`;
- `InvalidContextFailures`/`InvalidContextFailuresWrapCount`;
- `LastFailedRequestedBytes`, `LastFailedAdjustedBytes`;
- `LastFailureReason` (`UInt32`), `LastFailureReasonText` (`String`),
  `LastFailureTimestamp` (`DateTime`) and `LastFailureUptimeMs` (`UInt64`).

`UsedBytes` is `TotalBytes - FreeBytes` and therefore includes allocator
metadata and fragmentation. Do not enlarge every FreeRTOS allocation header
to add payload-only tracking. Preserve the legacy
`Device.Diagnostics.FreeHeap` and `MinEverFreeHeap` NodeIds/types as views of
the same snapshot; they do not own duplicate state.

Change `vApplicationMallocFailedHook` from a terminal policy owner into a
non-allocating recorder: it updates wrapping counters (with saturating wrap
counts), records the last failure and returns. Audit every enabled allocation
path and define its `NULL` behavior;
every first-party direct caller requires a focused test, and a generic failure
must not silently continue. Allocation from ISR is unsupported: Debug asserts,
while Release returns failure and increments `InvalidContextFailures`.

A handled runtime allocation failure does not set `LastFaultCode`; doing so
would automatically drive the existing `device_health_service` to `Failure`
and emit its existing condition. This T2 vertical adds no memory alarm/event
or DeviceHealth transition. Failure to create `InitTask` or any required
long-lived task (`NetworkTask`, `SensorTask`, `TimeTask`, `AlarmTask`,
`OpcUaTask`, `WatchdogTask`) is critical: set
`DIAG_FAULT_CODE_MALLOC_FAILED`, do not report the device ready, and enter the
existing watchdog-recovery path.

### PSRAM and nested lwIP arena nodes

Extend the existing always-present, read-only `Device.Diagnostics.PSRAM`
folder with the current nodes preserved. The complete required surface is:

- existing `Ready`, `TotalBytes`, `UsedBytes`, `FreeBytes`,
  `LargestFreeBlockBytes`, `AllocatorMode`;
- new `PeakUsedBytes`, `RequestedBytesInUse`,
  `PeakRequestedBytesInUse`;
- `SuccessfulAllocations`/`SuccessfulAllocationsWrapCount`;
- `SuccessfulFrees`/`SuccessfulFreesWrapCount`;
- `FailedAllocations`/`FailedAllocationsWrapCount`;
- `LockTimeouts`/`LockTimeoutsWrapCount`;
- `InvalidContextFailures`/`InvalidContextFailuresWrapCount`;
- `LastFailedRequestedBytes`, `LastFailureReason`,
  `LastFailureReasonText`, `LastFailureTimestamp`, `LastFailureUptimeMs`.

Top-level `UsedBytes` remains `TotalBytes - FreeBytes`, including allocator
metadata, fragmentation and the whole reserved lwIP arena.
`RequestedBytesInUse`/`PeakRequestedBytesInUse` report live caller-requested
payload tracked at the PSRAM allocation boundary. `calloc` multiplication
overflow is a failed allocation; failed `realloc` preserves the old block;
`realloc(ptr, 0)` is a free. Instrument public allocator operations so a
moved `realloc` is not double-counted as two caller operations.

Protect the PSRAM free list and its counters with a statically allocated
FreeRTOS mutex. Calls before scheduler start are single-threaded. Once the
scheduler runs, allocation, `calloc`, `realloc` and stats-snapshot acquisition
use a fixed 10 ms timeout; timeout returns failure and increments
`LockTimeouts`, independently from out-of-memory failures. ISR calls follow
the Heap Debug/Release policy above. When `ua_port_alloc` first fails in PSRAM
and then succeeds through its SRAM fallback, record one PSRAM failure and one
successful FreeRTOS allocation.

Deallocation is the deliberate exception to the failure-return rule because
the compatibility-preserved `psram_free(void *)` and open62541 `UA_free` chain
cannot propagate failure or retry safely. It must be non-failing and bounded:
try the mutex for 10 ms; if that interval expires, increment `LockTimeouts`
once and transfer the allocation atomically onto an intrusive pending-free
list stored in the released block's own allocator metadata. This list performs
no allocation and is inherently bounded by the number of live blocks. The
next successful locked allocator or one-second stats-snapshot operation drains
and coalesces it. A pending block remains part of arena `UsedBytes` until it is
drained, but leaves `RequestedBytesInUse` when ownership transfers.

`psram_free` returns only after either immediate reclamation or successful
pending-list ownership transfer, which is its acknowledgement to the void
caller. Reorder `ua_port_free` so it does not invalidate its allocation header
before that acknowledgement. Detect double/invalid/deferred frees without
corrupting either list. Concurrency tests must prove bounded enqueue time,
eventual drain, no lost/double free, and correct accounting. No separately
allocated queue, silent leak, blocking forever or watchdog recovery is
permitted on this path.

The lwIP heap is a nested allocator inside one permanently reserved PSRAM
arena, so top-level PSRAM use alone cannot describe network pressure. Add the
read-only folder `Device.Diagnostics.PSRAM.LwIP` with `ReservedBytes`,
`UsedBytes`, `PeakUsedBytes`, `LargestFreeBlockBytes`, and
`FailedAllocations`/`FailedAllocationsWrapCount`. Its accounting must come
from the actual bounded lwIP arena and must not be added again to top-level
PSRAM use.

For Heap and PSRAM, the stable `LastFailureReason` values are:
`0=None`, `1=OutOfMemory`, `2=LockTimeout`, `3=InvalidContext`,
`4=SizeOverflow`; never renumber an assigned value. Heap never reports
`LockTimeout`. Store failure uptime at the allocation boundary. Capture
`LastFailureTimestamp` only if wall time is valid at the failure; otherwise
leave it null for that failure and never backfill an invented time later.

If PSRAM is not compiled for a profile, its data values are
`BadNotSupported`. If compiled but initialization failed, they are
`BadNotConnected`. A failed snapshot refresh retains the last coherent values
with `UncertainLastUsableValue`.

### Named task model

Add `Device.Diagnostics.Tasks.<ActualFreeRTOSTaskName>` dynamically from
`OpcUaTask`, which is the sole owner of address-space mutation. Use the exact
post-truncation FreeRTOS name in the String NodeId and BrowseName; spaces such
as `Tmr Svc` are valid. Do not expose `Slot00..Slot15` names. Handle duplicate
actual names with the explicit incomplete-model policy above; do not invent a
suffix that makes NodeIds depend on task creation order.

Create/discover this folder and its dynamic children only when the persisted
`enable_task_diagnostics` setting is true, preserving the existing switch's
meaning. The native bounded snapshot/counters may continue independently so
enabling OPC UA exposure never changes their lifetime semantics.

Node discovery is dynamic because `opcua_model_init` is invoked before the
application creates `NetworkTask`, `SensorTask`, `TimeTask`, `AlarmTask`,
`OpcUaTask` and `WatchdogTask`, while actual server/address-space construction
runs later on `OpcUaTask`; FreeRTOS/lwIP also create internal tasks and the
transient `InitTask` later disappears. Do not depend on one boot scheduling
order or on the existing eight-entry registered-application-task table.

One-second polling alone can miss a task created and deleted between samples.
Use bounded, non-allocating FreeRTOS task create/delete trace hooks to retain
unique-name lifecycle and generation state from creation onward, including
pre-scheduler Idle/Timer creation. Bootstrap any task that predates hook/service
readiness and keep the explicit InitTask registration path. The one-second
`uxTaskGetSystemState()` sample supplies live runtime/state/HWM values and
reconciles hook state; hooks do not mutate the OPC UA address space.

The hook ingress is one static 16-record table, initialized safely before any
task hook can run and retained across `diag_service_init`. A create hook copies
the post-truncation name and captures the handle identity/generation before it
returns; a delete hook finds that identity, marks it absent and clears the
stored handle before the TCB can be freed. Hooks run inside the kernel's task
critical region: they perform only a bounded table scan and fixed-size copy,
never allocate, log, take the snapshot mutex, call OPC UA, or retain a pointer
to a TCB-owned name. The seventeenth unique name sets the sticky truncation
flag; a duplicate live name sets the conflict/incomplete flags.

The sampler copies ingress state under a short task critical section, then
uses the self-contained records returned by `uxTaskGetSystemState()` and
matches identity values without dereferencing a retained handle. Once a delete
event is observed, no later code may call `vTaskGetInfo`, `pcTaskGetName` or
another TCB accessor through that old handle. Test create/delete racing the
sample, deletion immediately after system-state capture, and immediate TCB
address reuse; generation and name must remain correct without use-after-free.
On first observation of a unique name, create its bounded object. Never delete
that object during the boot: after task deletion, keep it with `Present=false`
and `State=Deleted`. Recreation under the same name increments `Generation`.
After 16 unique names, do not create a seventeenth object and set
`TaskListTruncated=true`.

Build each dynamic task subtree transactionally on `OpcUaTask`. If any node
addition fails, roll back only that incomplete subtree, retain the native task
record, set `TaskModelIncomplete=true`, and make at most one construction
attempt per later one-second cycle until it succeeds. Do not allocate a retry
queue or block sampling. Clear the flag only when every retained task name has
a complete subtree, `TaskNameConflict=false`, and no unique-name-capacity
overflow occurred. Test partial-add rollback, several consecutive allocation
failures, bounded repeated retries, eventual recovery, and conflict-flag
persistence/recovery explicitly.

Every task object is read-only and contains:

- `Present: Boolean`, `Name: String`, `TaskNumber: UInt32`;
- `Generation: UInt64` and `GenerationWrapCount: UInt64`;
- `State: UInt32` and `StateText: String`;
- `CurrentPriority: UInt32`, `BasePriority: UInt32`;
- `RuntimeCounterMs: UInt64`, `RuntimeCounterWrapCount: UInt64`, and
  `RuntimePercent: Double` calculated from the one-second delta;
- `StackHighWatermarkBytes: UInt64` (convert from `StackType_t` units).

Define the public state enum independently from `eTaskState`:
`0=Running`, `1=Ready`, `2=Blocked`, `3=Suspended`, `4=Deleted`,
`5=Invalid`; do not leak FreeRTOS numeric values. For `Present=false`, fields
other than identity/generation/presence/state have `BadNoData`.

The native run-time source is the configured 32-bit millisecond counter. For
each task generation, extend it monotonically to `UInt64` from contiguous
valid samples: if the new raw value is lower, account for one native 32-bit
wrap before adding the modulo delta. `RuntimeCounterWrapCount` counts overflow
of the published `UInt64` lifetime value under the general counter rule; the
internal native-wrap accumulator is not a separate public metric. A sampling
gap shorter than `2^32` ms still has an unambiguous modulo delta because a task
cannot accumulate more CPU time than elapsed monotonic time. If the gap is
`2^32` ms or longer, retain the last counter as
`UncertainLastUsableValue` because the number of native wraps is not provable.

`RuntimePercent` is `100 * task_delta / total_runtime_delta` for two
successive complete samples of the same generation. It is `BadNoData` for the
first valid sample, zero total delta, truncated/incomplete samples, deletion,
and the first sample after recreation or an unprovable gap. The next
contiguous valid pair restores `Good` quality. Extend the native 32-bit total
runtime counter with the same wrap/gap rules before calculating its delta.
Add deterministic tests for task and total native 32-bit wraps, first sample,
zero denominator, truncation, deletion and generation reset.

Preserve the existing `Device.Diagnostics.Task.OPC`, `.SPI` and `.TEMP`
`StackHighWatermark` NodeIds, BrowseNames, `UInt32` types, legacy task mapping
and existing `StackType_t`-word units as compatibility views of the same
snapshot. Do not silently relabel those old values as bytes. Only the new
named-task `StackHighWatermarkBytes` nodes perform the explicit
`sizeof(StackType_t)` conversion.

### OPC UA access and publication

All new snapshot-root, Heap, PSRAM-extension, lwIP and named-task nodes are
read-only and non-historizing. Only authenticated `service` and `admin` roles
may Browse or Read them; `viewer`, `operator` and anonymous sessions must not
see them in Browse and receive `BadUserAccessDenied` on a direct Read.
Retained legacy diagnostic nodes preserve their existing permissions.

Subscriptions publish no faster than the one-second snapshot cadence. The
vertical adds no diagnostic alarm/event and no reset Method. Public NodeIds,
BrowseNames, types, units, role behavior and quality codes require automated
source-contract plus live asyncua tests and UaExpert inspection. Compare the
resulting inventory against released v0.5.1 and document every additive node.

### Resource budget and verification gate

The instrumentation itself is bounded to:

- at most 4 KiB additional internal SRAM (`.data + .bss`);
- at most 128 KiB additional PSRAM with all 16 named task objects present;
- no more than 256 bytes reduction in `OpcUaTask` stack high-water reserve
  under an otherwise identical v0.5.1 workload; and
- at most 2 ms p99 to collect a snapshot. Dynamic OPC UA node construction is
  measured separately and is not hidden inside the sampling latency number.

Exceeding a budget fails T2. Report the measured delta and redesign before
changing a limit; do not silently relax it.

Required host/mock tests cover positive reads, all role combinations, direct
Read versus Browse hiding, write denial, invalid input, size overflow,
counter/wrap behavior, 16-task capacity, duplicate/truncated names, deleted
and recreated tasks, `uxTaskGetSystemState()` overflow, unavailable/stale
quality, mutex timeout, concurrent allocator/snapshot access, `calloc` and
`realloc` semantics, PSRAM-to-SRAM fallback and each failure reason. Injected
failures must prove every affected first-party caller handles `NULL`.

Add a dedicated compile-time reference-board exhaustion-test firmware profile;
it is excluded from production images, exposes no public memory-exhaustion
Method, does not write persistent Flash/configuration, and emits bounded JSON
over USB serial. On actual reference hardware run 100 fill/fail/free cycles
for FreeRTOS Heap and 100 for PSRAM. Verify no reboot or corruption, exact
failure-counter increments, return of `UsedBytes` to its pre-cycle baseline,
and no further decrease in `MinimumEverFreeBytes` after the first stabilized
cycle. Record board/firmware/toolchain identity, raw JSON, runtime memory and
stack deltas, and label the result as reference-board validation only; it is
not industrial-board qualification.

## Benchmark matrix and evidence rules

The requested axes are 1/4/8/16 synthetic channels, REDUCED/FULL Namespace 0
where supported, test-only security off versus Basic256Sha256 SignAndEncrypt,
1/2/4 clients, 1/10 Hz sampling/subscription load, and events/history
enabled/disabled. T0 must state which combinations are supported and how
each supported combination is exercised; list unsupported cells and their
cause explicitly. A missing run is not a passed or zero-valued measurement.

Every report identifies schema/profile ID, firmware version and exact Git
commit/dirty state, board revision, driver pack, Namespace 0 mode, security,
toolchain/build flags, configured capacities, channel count, periods, client
versions/count, network/test setup, time synchronization state, warm-up,
duration/repetitions and operation/sample/error counts. Record units and
