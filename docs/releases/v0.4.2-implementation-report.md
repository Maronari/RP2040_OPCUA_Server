# v0.4.2 implementation report

## Status

As of August 15, 2026, the Generic OPC UA Channel Information Model is a
**release candidate** in the current working tree. The implementation,
automated release gates, independent review, reference-device factory boot,
authenticated OTA update, reboot, reconnect, and post-update health checks
pass.

The release is not classified as accepted because UaExpert is not installed in
the verification environment. Runtime PSRAM was measured, but the task-stack
high-watermark diagnostic nodes returned `BadNotFound`.

The implementation and this report are recorded together in the v0.4.2 release
candidate commit; its exact SHA is reported from Git rather than embedded as a
self-reference in the commit contents. No release tag was created. The
immutable comparison baseline remains v0.4.1 commit
`a5ebc3231faf658325ad02e997f05acf8601e8bf`. `ROADMAP.md`, `AGENTS.md`, and
`docs/releases/v0.4.2.md` were not modified as part of this report.

## Scoped implementation outcome

- Added one generic OPC UA channel hierarchy created at server startup from
  bounded channel-registry snapshots.
- Kept services as the sole owners of channel metadata, runtime values,
  quality, source timestamps, synchronization, and driver operations.
- Added a copied service-owned source descriptor containing `driver_id`,
  `source_index`, and `source_flags`.
- Added a generation-safe, exclusive service write lease. Driver calls occur
  outside the registry critical section and no unbounded operation queue was
  introduced.
- Exposed the exact OPC UA built-in type for every accepted channel value type:
  `Float`, `Double`, `Int32`, `UInt32`, `Int64`, `UInt64`, `Boolean`, and
  bounded `String`.
- Propagated value, quality, and source timestamp from one coherent snapshot.
- Added standard `EUInformation` and `Range` properties when configured.
- Preserved all unrelated v0.4.1 public contracts and retained the legacy
  temperature NodeId as a stateless view of the same registry-owned sample.
- Added deterministic partial-build rollback and bounded model contexts.
- Did not add the v0.4.3 multi-channel history/alarm engine or the v0.5.0 live
  model-regeneration work.

## Public OPC UA contract

The generic namespace URI is:

```text
urn:maronari:rp2-industrial-opcua:channel-model
```

Clients resolve the namespace URI instead of assuming its runtime namespace
index. The exact deterministic NodeId grammar is:

```text
nsu=urn:maronari:rp2-industrial-opcua:channel-model;s=Device.Channels.c_<encoded-id>
nsu=urn:maronari:rp2-industrial-opcua:channel-model;s=Device.Channels.c_<encoded-id>.<field>
```

`<encoded-id>` is the uppercase hexadecimal encoding of each UTF-8 byte of the
validated channel ID. NodeIds do not depend on registry slot, registration
order, generation, addresses, boot state, or driver pointers.

The exported public-contract inventory against tag `v0.4.1` passed with final
inventory SHA-256:

```text
405888c68a891422081f3b75d79a7c8ba3dcd7e6dff14599a12417e995f546c4
```

The bounded 12-node generic NodeSet export was byte-identical before and after
the authenticated OTA reboot:

```text
132ee3f7efdb61022de61f2d17f53e112a11446ae8aefa5b604ec55cd4cd3de1
```

The complete model contract is documented in `docs/channel_model.md`.

## Hardware defects found and fixed during the release gate

### OPC UA listener recovery

The lwIP open62541 listener was closed after recoverable `accept()` failures,
which left the device pingable while TCP port 4840 refused new connections.
The listener now remains open for the bounded transient/capacity error set,
including `EAGAIN`, `EWOULDBLOCK`, `ENFILE`, `ENOMEM`, and `ENOBUFS`.

The target stress check attempted 24 connections, held 3 at capacity, observed
21 deterministic rejections, released the held connections, and successfully
opened a fresh SecureChannel. COM6 logs showed timed-out SecureChannels closing
without closing the server socket.

### Factory bootloader handoff

The factory image originally enumerated an unusable USB device and never
started Ethernet. The bootloader enabled USB stdio but handed Bank A stale
enabled/pending NVIC state. The application re-enabled interrupts during its
pre-main Pico SDK initialization before installing its own USB handler, so an
inherited USBCTRL interrupt entered the application's unhandled IRQ trap.

The handoff now, while keeping interrupts globally masked:

1. disables both RP2350 NVIC banks;
2. holds USBCTRL in reset;
3. clears both pending-interrupt banks;
4. stops SysTick;
5. transfers VTOR and MSP to Bank A;
6. branches to the application reset handler without re-enabling interrupts.

The redundant second `multicore_reset_core1()` was removed from the handoff,
eliminating an unnecessary unbounded ROM FIFO wait. The corrected factory UF2
cold-booted successfully with COM6 and OPC UA available.

### Resumable OTA client

Erasing Bank B can outlive the initial SecureChannel. The OTA service correctly
kept its bounded session, but the client had no safe way to continue it.
`stage_ota.py` now supports explicit `--resume-active` only when the remote
size, CRC32, version, offset, remaining byte count, and the selected local
manifest agree. Before any connection or device mutation it streams the local
payload in bounded 64 KiB chunks and verifies both CRC32 and SHA-256.

Resume transport failures do not request an automatic abort. Operators must
query device status before another explicit resume. Manifest or offset mismatch
fails closed.

## Additional review after `fa0c627`

The additional v0.4.2 review found two implementation defects and one release
evidence gap.  Channel rebuild detection omitted startup-materialized metadata,
and rollback of a failed legacy compatibility subtree was not included in the
channel-model transaction.  The exact generic `Value` failure hypothesis was a
false positive: deleting its generic parent recursively deletes that child in
the bundled open62541 implementation.  The legacy subtree omission was real and
is now cleaned locally and by the bounded transaction rollback.

The discovery verifier now requires explicit channel-to-VariantType mappings
when mixed coverage is requested.  Writable verification changes the value
using its exact built-in type, reads the changed value back, restores the
original value, checks wrong-type rejection, and can require a second client to
receive `BadUserAccessDenied`.  A local asyncua client/server integration test
exercises mixed `Double`/`UInt32`, read-only rejection, writable mutation and
readback, restoration, and wrong-type rejection.  This test validates the
client gate itself; it is not firmware-target evidence.

Local additional-review results:

- reference RP2350 Debug configure/build: PASS;
- host runner: PASS, 28 suites;
- injected runner failure: expected exit code `1`;
- first-party cppcheck 2.19.0: PASS, zero findings;
- artifact, version `0.4.2`, v0.4.1 public-contract, and `git diff --check`

### Network OTA: failed, safe rollback

Authenticated network OTA (`stage_ota.py`, `--reboot-after-finalize`) to the
confirmed endpoint required four sessions because the SecureChannel dropped
repeatedly (immediately after `BeginFirmwareUpdate`, then again at 7.3% and
90.6% of the write). `--resume-active` correctly continued each time from the
device-reported `bytesWritten` offset and reached
`FinalizeFirmwareUpdate`/`STAGED_IN_BANK_B` with the expected size
(3,304,912 bytes) and CRC32 (`0xe02c8306`). On reboot the bootloader's own
`ota_flash_verify_bank_b`/vector-table check rejected the staged image
(`otaState: FAILED`, `otaLastError: INVALID_STAGED_IMAGE`) and the device
correctly fell back to the previously running Bank A image; no data outside
Bank B was affected and the device remained fully healthy throughout
(`verify-channel-model: PASS` immediately after the failed attempt, still
reporting `gitHash: a5ebc3231faf`).

One resume session logged an internal `asyncua` client error
(`Future for request id 91 is already done`) partway through the transfer.
`WriteFirmwareChunk` carries no explicit offset argument and relies on strict
per-session request/response ordering, so a client-side response/request
mismatch during a dropped-and-resumed session is the most likely explanation
for the final image failing the bootloader's CRC32/vector check even though
`bytesWritten` bookkeeping looked consistent at every status checkpoint. This
was not fully root-caused and is flagged here as a known risk of resuming a
firmware upload across multiple reconnects with the current `asyncua`-based
client; it did not affect device safety because the bootloader's independent
staged-image verification caught it before any boot attempt.

### USB BOOTSEL recovery: verified

With the user's authorization to flash the bootloader together with the
application, the combined factory image (bootloader + Bank A app) was built
via the `ota_artifacts` CMake target, which requires reconfiguring with
`-DOTA_BUILD_BOOTLOADER=ON` (the reference `OFF` configuration used elsewhere
in this report does not produce `device_profile_basic_bank_a` or
`ota_bootloader`). The `ota_artifacts.cmake` UF2-conversion step failed in
this environment because `${picotool_INSTALL_DIR}` was empty; `picotool.exe`
was invoked directly from `build/_deps/picotool/picotool.exe` with the same
arguments as a workaround. This CMake-cache-population gap in the
`OTA_BUILD_BOOTLOADER=ON` path is a build-system defect worth a follow-up fix;
it did not affect the resulting `factory_full.uf2` content.

The device was switched to BOOTSEL by the user and enumerated as a `RPI-RP2`
mass-storage drive (`Board-ID: RP2350`; USB instance serial
`C3F9822180D224D1`, matching the OPC UA-reported serial). Copying
`factory_full.uf2` to the drive flashed and rebooted the device. Post-flash
verification:

- device identity: `gitHash: fa0c627491c9` (the additional-review build),
  `softwareRevision: 0.4.2`;
- `verify_channel_model.py` full check (`--expect-legacy-temperature`,
  `--verify-history`, `--verify-read-only-write`): `PASS`;
- `verify_listener_recovery.py` (24 connections, 3 held, 21 rejected,

- exported `Device.Channels` NodeSet (12 nodes): SHA-256
