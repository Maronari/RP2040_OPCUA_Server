# v0.3.3 — Maintenance Journal and Condition Semantics

## Status, baseline, and scope

Unreleased; first unreleased version in `ROADMAP.md`. Immutable implementation
baseline: tag `v0.3.2`, commit
`f9336396f1102002eeb28bc7241c05de268d72aa`.

Add only bounded persistence/recovery for the v0.3.2 maintenance workflow,
bounded export/reset, recovered condition semantics, diagnostics, and live
Audit Events. Preserve all v0.3.2 NodeIds, BrowseNames, method signatures,
roles, status mappings, transitions, and transition-event cardinality.
Historical Event Access, arbitrary/general event persistence, new AMB states,
and a general storage abstraction remain out of scope.

## Fixed resource and Flash contract

Reserve eight 4096-byte sectors (32768 bytes) in authoritative
`ota/cmake/ota_layout.cmake`, subtracting them from the bank pool before its
even split. The region must not alias either firmware bank, bootloader,
configuration slots (including the v0.3.2 final-sector driver), identity,
trust, security-state, or OTA-state storage. Generated header/JSON, linker
layout, and `ota_layout_sanity.c` must assert alignment, ordering, and
non-overlap.

Each sector has one immutable, once-programmed 256-byte header page and three
1024-byte record slots (the final 768 bytes stay erased/reserved): 24 physical
slots total. Sector-relative ranges are header `0x000-0x0ff`, records
`0x100-0x4ff`, `0x500-0x8ff`, and `0x900-0xcff`, and reserved
`0xd00-0xfff`. At most
15 records are logically retained. A rotation-triggering mutation temporarily
has 16 valid records (15 old plus its new checkpoint) before the oldest whole
three-record sector is retired. At least two fully erased sectors must exist
before initializing a successor: one candidate and one remaining erase-ready
spare. Thus at most six sectors are non-erased transiently, and mutation/reset
never consumes the final erased sector. With fewer than two erased sectors, the
backend may first erase a sector containing neither the current snapshot nor a
retained record; otherwise it returns the fixed storage-capacity status without
programming or erasing. Recovery reads at most eight headers and 24 slots.
Export returns at most four logical records per page. Four continuations may
exist; they expire after 30 seconds and retain only
`{epoch,newest_sequence,next_index}`. Codec/backend scratch buffers are at most
1024 bytes each, statically/PSRAM allocated, never task-stack buffers. Build
checks fix record/header size, scan work, buffers, and worst-case stack.

Acceptance: generated-layout tests prove exact bounds/non-overlap; capacity,
fifth-continuation, expiry, full-region, scan-count, and stack/buffer checks
fail deterministically.

For the 16 MiB reference target, the authoritative expressions add the
32768-byte journal to `OTA_LAYOUT_RESERVED_BYTES` before the even bank split:
`(0x1000000 - (0x90000 + 0x8000)) / 2 = 0x7b4000`. The exact map is bootloader
`0x000000-0x00ffff`; bank A `0x010000-0x7c3fff` (offset `0x010000`, size
`0x7b4000`); bank B `0x7c4000-0xf77fff` (offset `0x7c4000`, size `0x7b4000`);
journal `0xf78000-0xf7ffff`; configuration slots `0xf80000-0xf8ffff` and
`0xf90000-0xf9ffff`; identity slots `0xfa0000-0xfaffff` and
`0xfb0000-0xfbffff`; trust slots `0xfc0000-0xfcffff` and
`0xfd0000-0xfdffff`; security state `0xfe0000-0xfeffff`; OTA state
`0xff0000-0xffffff`.

## Canonical record codec

Files: new `maintenance_journal_codec.[ch]`, host codec/recovery tests, and
`docs/maintenance_journal.md`. The public codec accepts caller-owned byte spans
and contains no Pico SDK, Flash, FreeRTOS, open62541 types, or native-struct
serialization.

### Exact byte budget

The first three pages provide 768 bytes before the commit page:

| Field | Maximum bytes |
| --- | ---: |
| Header: magic 4, schema 2, type 1, flags 1, encoded/header lengths 2+2, epoch 8, sequence 8, operation 1, transition 1, reserved 2, command timestamp 8 | 40 |
| Snapshot: state 1, revision 4, committed timestamp 8, has-activity 1 | 14 |
| Activity fixed: planned timestamp 8, downtime binary64 8, method 1, configuration-changed 1, part counts 2 | 20 |
| Operation ID (`u8` length + 47 payload) | 48 |
| Supplier (`u8` length + 47 payload) | 48 |
| Personnel (`u8` length + 47 payload) | 48 |
| Actor (`u8` length + 31 payload) | 32 |
| Result (`u8` length + 95 payload) | 96 |
| Serviced parts: 4 × (`u8` length + 47 payload) | 192 |
| Replaced parts: 4 × (`u8` length + 47 payload) | 192 |
| CRC-32 | 4 |
| Required encoded bytes | **734** |
| Reserved schema-extension margin | **32** |
| Required erased padding | **2** |
| Dedicated commit page | **256** |
| Slot total | **1024** |

Implementation must `_Static_assert` `MAX_ENCODED_SIZE == 734`,
`MAX_ENCODED_SIZE + EXTENSION_MARGIN <= 768`, and
`RECORD_SLOT_SIZE == 768 + FLASH_PROGRAM_SIZE`; host tests recompute the table
from the public capacity macros. Schema 1 cannot consume the extension margin.

### Canonical primitives

Integers are exact-width unsigned or two's-complement signed, little endian.
Enums are `u8` and accept only defined values. Booleans are exactly `0x00` or
`0x01`. Downtime is IEEE-754 binary64: encode its `uint64_t` bit pattern little
endian, reject NaN, both infinities and out-of-range values, and canonicalize
negative zero to positive zero.

Strings are `u8` byte length plus that many UTF-8 bytes; the native terminating
NUL is not stored. Maximum payload is capacity minus one. Reject embedded NUL,
missing native termination, invalid/overlong UTF-8, surrogates, and oversize
input. Empty strings follow existing service validation. Unused part entries
encode length zero; counts are 0..4 and later entries must be empty. Every
reserved, extension, padding, and unused commit-page byte must be `0xff`.

CRC is CRC-32/ISO-HDLC: polynomial `0x04c11db7` (reflected
`0xedb88320`), init `0xffffffff`, refin/refout true, xorout `0xffffffff`, no
augmentation; check `0xcbf43926` for ASCII `123456789`. It covers the first
`encoded_length - 4` bytes; stored CRC is the final four encoded bytes. It
excludes extension/padding and commit page.

The 256-byte commit page contains the supported 32-bit pattern and erased
reserved bytes. Only a supported, structurally valid, CRC-valid record with
that exact page pattern is visible. `RESET` embeds the current snapshot.

Invariants: decode failure produces no output; host layout/endianness cannot
change bytes; unchecked fields are never exported. Acceptance: golden vectors
for both types plus every length boundary and mutations of every covered field,
CRC, marker, padding, truncation, and maximum activity data.

## Transaction ordering

The adapter, service, codec, and backend use this exact order:

1. Authorize and validate arguments, source state, journal writability,
   capacity, and bounded OPC UA/event resources without mutation.
2. Under the service transaction lock, copy the active snapshot; prepare the
   complete candidate; allocate epoch/sequence; encode its record in RAM.
3. Program all record bytes except the commit word into an erased slot.
4. Read back and validate structure, schema, lengths, tuple, complete snapshot,
   and CRC against the RAM candidate.
5. Program the commit page only after payload read-verification. A torn write
   must not produce the exact supported page accidentally; recovery accepts
   only that pattern plus erased reserved bytes. Read-verify it.

   For an append into an already authoritative sector, successful commit-page
   verification is the durability point.

   For the first record in a successor, successful commit-page read-verification
   is also the sector-authority and durability point: recovery accepts the
   sector only when its immutable header, predecessor/generation lineage, and
   first committed record all validate. Before that point the predecessor
   remains authoritative.
6. After the applicable durability point, infallibly switch the service active
   index/revision directly to the prepared RAM candidate. Never rescan Flash on
   the normal commit path. The service snapshot must not switch before the
   successor authority point.
7. Synchronize the OPC UA model/condition from that committed snapshot.
8. Trigger exactly one prepared transition event for Plan, Start, or Finish
   (none for Reschedule), then publish applicable live Audit Events.
9. Update diagnostics, release the transaction, and only then return.

No Method returns `Good` or switches the RAM snapshot before the applicable
commit-page verification; every successful result is reboot
recoverable. Failure through step 4 leaves old RAM state and an ignored
incomplete slot. After step 5, the service switch cannot fail. OPC UA sync,
transition publication, and Audit publication are separate fallible
post-commit phases: failure records a bounded degraded/fault diagnostic,
preserves durable/service state, blocks later mutation per the v0.3.2 fault
policy, and reconciles from active RAM. Never append compensation, roll back,
or rescan Flash on this path. Event failure consumes no record. Before coding,
verify backend program granularity/alignment, erased-page programming, and all
selected Flash/Pico SDK repeated-program restrictions.

Acceptance: inject failure before and after every step, including torn
immutable-header writes, power loss before/after first-successor commit
read-verification, and after successor authority but before the service RAM
switch. Assert Method
status, pre-reboot state, recovered revision/snapshot, and v0.3.2
transition-event cardinality.

## Sector lifecycle

The canonical little-endian 256-byte header is programmed exactly once after
erase. It contains magic, format/header versions and length, 64-bit epoch and
generation, predecessor epoch/generation, sector index, reserved bytes, and
CRC-32; all padding is `0xff`. CRC covers the immutable fields before CRC.
There is no persistent lifecycle/state word and no header page is programmed
twice. A torn or noncanonical header is unusable.

Lifecycle is recovered, not written. A valid header with no valid first record
is an uncommitted candidate. Its first committed record establishes authority
only when header, lineage, record, CRC, and commit page all read-verify. Valid
lineage may temporarily expose predecessor and successor; record tuples select
the newest. Sectors outside the retained lineage are reclaimable only when
they contain neither the current snapshot nor a retained record. Erase plus
erased readback makes one erased again. The rotation checkpoint is the complete
first successor record; only its authority point permits retention reduction,
RAM switch, or `Good`. A cut during the immutable header or before first-record
commit leaves the predecessor authoritative; a cut after commit recovers the
successor. Torn/contradictory headers are never autoformatted.

Invariants: no erase without another validated committed current snapshot;
authority never moves backward; retention reduction never crosses the current
record or consumes the final spare; lifecycle operations are idempotently
recoverable. Acceptance: exercise all 24 physical slots, 15 retained and 16
transient records, zero/one/two erased-sector cases, and power cuts at every
immutable-header byte/page, record body, commit, checkpoint, erase, and readback boundary;
always retain the last acknowledged snapshot.

## Epoch, generation, and sequence

Epoch, sector generation, and record sequence are unsigned 64-bit; `0` and
`UINT64_MAX` are reserved. Reset increments epoch and starts generation/sequence
at `1`; successor authority increments generation within an epoch; snapshot
append increments sequence. Interrupted allocation may create gaps but a
`{epoch,sequence}` tuple is never reused.

Ordering is RFC-1982 serial arithmetic: `a` is newer than `b` only when
`0 < (a-b) mod 2^64 < 2^63`. Equality and exact half-range are unordered. The
enforced resident window is at most 24 records, eight generations, and two
adjacent epochs. Before increment reaches a reserved value or could violate
that window, mutation fails closed; there is no silent wrap. Compare epoch,
then generation lineage, then sequence within epoch. Equal tuple with identical
canonical bytes is a harmless reclaim copy; unequal bytes, broken lineage, or
half-range distance is fatal ambiguity.

Acceptance: reserved values, gaps, rollover refusal, adjacent epochs,
half-range, legitimate lineage, identical duplicates, and conflicting
duplicates.

### Service revision

The existing `uint32_t revision` is encoded little endian in every snapshot
and is independent of the 64-bit journal tuple. Each accepted Plan,
Reschedule, Start, or Finish sets candidate revision to active revision + 1,
as in v0.3.2. Reset preserves revision because workflow state is unchanged.
Reboot restores revision verbatim from the selected record; it is never
derived from epoch, generation, or sequence. Epoch orders resets, generation
orders sectors, and sequence orders persistent records.

Revision `0` is invalid. At `UINT32_MAX`, workflow mutations are refused before
prepare/program; Reset remains allowed because it preserves revision but does
not cure overflow. Revision never wraps or reuses an ambiguous value.
Acceptance: append, reset, reboot, reclaim, `UINT32_MAX-1 -> UINT32_MAX`,
refusal at `UINT32_MAX`, and independence from journal counters.

## Recovery and corruption policy

Recovery completes before OPC UA maintenance exposure. Scan all eight headers,
then all three slots of every committed header; never stop at an erased/bad
slot because torn append/reclaim can leave holes.

- Wholly erased media restores v0.3.2 `Finished`, revision `1`, and initializes
  Flash only on the next mutation.
- Erased slots are free. Erased commit means incomplete append. Any other bad
  commit value, committed CRC/structure failure, or impossible slot is corrupt.
  Count it and continue.
- A bad/uncommitted header makes only that sector unusable; continue elsewhere.
- Unknown committed sector/record schema is preserved, never decoded, exported
  as fields, erased, or overwritten.
- Multiple active sectors require consistent epoch/generation/predecessor
  lineage; otherwise they are ambiguous.
- Older isolated corruption with an unambiguous newer supported snapshot gives
  `DEGRADED` recovery.
- Fail closed for non-erased media with no supported snapshot, a newer unknown
  schema, conflicting duplicate, half-range order, contradictory lineage, or
  ambiguous newest record. Expose only any last unambiguous snapshot for reads;
  disable mutation/reset. Never repair or erase during recovery.

Acceptance: erased media, incomplete tail, every marker class, CRC failure,
corrupt committed record/header, unknown schema, two legitimate/contradictory
active sectors, degraded older corruption, and every fail-closed case.

## Crash-safe journal reset

Reset is admin-only and is not bulk erase presented as atomic. After preflight,
create a successor with epoch + 1/generation `1`; program/verify a `RESET`
record at sequence `1` containing the current snapshot; commit and read-verify
it; then expose the new epoch. That authority point is the logical reset:
normal export excludes older epochs while reboot still restores workflow state.

A reset also requires two erased sectors before successor initialization and
cannot consume the final erase-ready sector. A cut before successful commit
read-verification preserves the old epoch; a cut after it makes the reset
authoritative. Old-epoch reclaim/erase is idempotent
cleanup and cannot reverse reset. If no successor can be made without erasing
the only current snapshot, return storage/capacity error and erase nothing.
Reset while the logical journal is already empty is idempotent and creates no
second tombstone. Emit exactly one success Audit Event only when a new reset
becomes active; rejection, interruption, reboot completion, and cleanup emit
none.

Acceptance: zero/one/two erased-successor cases plus cut/reboot/retry at every
phase; workflow state and revision stay unchanged, logical export is empty
exactly after successor authority, and one recoverable snapshot always remains.

## Export, conditions, events, and audit boundary

Export returns validated logical records in stable `{epoch,sequence}` order,
never raw Flash/offsets. A continuation pins its upper tuple: concurrent newer
appends are excluded; reset/reclaim invalidates it deterministically. Invalid,
expired, and capacity-exhausted tokens map to fixed status codes.

Condition `ActiveState`, `Retain`, `Severity`, `Message`, timestamps, and
`ConfigurationChanged` derive only from the coherent recovered/service
snapshot. `ConfigurationChanged` is the Finish result, not a generic
transition. Recovery synchronizes nodes/condition/diagnostics silently and
never fabricates an event.

Persistent maintenance-domain records are only accepted Plan, Reschedule,
Start, Finish snapshots and successful logical Reset. Rejections,
authentication/authorization failures, malformed calls, storage failures, and
event outcomes never consume slots. The one live transition event remains only
for successful Plan/Start/Finish. Volatile OPC UA Audit Events cover
accepted/rejected method calls, successful state changes, and successful Reset;
they are never persisted or replayed.

Rejected-call Audit Events use a bounded token bucket per session (burst four,
refill one/second) and device-wide (burst 16, refill eight/second). Suppression
updates only a counter and last-reason code per session; the next admitted
event reports that count once. Storage is bounded by the existing session
limit and cleared with the session; no dynamic queue is added. Accepted-call
and successful-change audits are not dropped by the rejected-call limiter and
use the existing bounded event-fault behavior.

Acceptance: stable paging/snapshot/expiry/reset invalidation; recovered state
text and NodeId plus every condition field; unchanged slot count for every
rejection; unchanged v0.3.2 transition cardinality; no replay; deterministic
limits/suppression with two abusive sessions; accepted calls remain auditable.

## Legacy storage prerequisite

`drivers/src/flash_storage_driver.c` is compiled into `FIRMWARE_DRIVERS`, and
`config_service_init()` can reach `flash_storage_driver_load_partial()` as a
fallback. Its save symbol has no call site, but remains linked; its
`PICO_FLASH_SIZE_BYTES - FLASH_SECTOR_SIZE` region is `0xfff000-0xffffff`,
inside authoritative OTA state `0xff0000-0xffffff`. Before journal work, retire
and disable this legacy backend. Migration policy: when both authoritative
configuration slots are invalid, a read-only importer may validate the legacy
record, commit/read-verify it to a configuration slot, and only then select it;
otherwise fail closed. It must never erase/program the legacy sector. Remove
the writer and production linkage after the documented compatibility window.
Layout/CI must reject the legacy range or any reachable legacy writer.

## Global Flash-operation coordination

Add only a minimal application-level coordinator: one statically allocated,
non-recursive FreeRTOS mutex owned by the coordinator and initialized before
any journal, OTA, configuration, identity/trust, or security writer starts.
Existing owners/APIs acquire it around each erase/program transaction. Domain
locks precede the Flash mutex; the Flash mutex must never acquire a domain lock.
Nested Flash transactions are prohibited and diagnosed.

Acquisition has a bounded timeout; timeout returns the subsystem's existing
busy/storage error without Flash mutation. While holding the mutex, call
`flash_safe_execute` exactly once per RAM-resident erase/program callback.
Callback, context, source buffer, and every reachable helper must be in RAM;
no logging, allocation, mutex, watchdog, or network call is allowed inside.
Safe-execute failure/timeout is an error, with readback required because the SDK
documents that a timeout may follow callback execution. Erases are one sector
and programs one page per lock hold; feed/check the watchdog outside the
callback, yield between units, and keep network service responsive. Bootloader
remains a separate single-writer image. Before release, measure worst-case and
p99 mutex wait, safe-execute enter/exit, page program, sector erase, watchdog
margin, packet loss, TCP/OPC UA latency, and disconnect/recovery during
concurrent writer attempts on reference hardware; measured limits must fit the
watchdog/network budgets.

## Stop conditions

Stop before implementation if the authoritative layout cannot reserve the
region without overlap; `git rev-list -n 1 v0.3.2` differs from the documented
full SHA; any linked/reachable legacy writer or legacy-region overlap remains;
all Flash writers cannot use the coordinator without nesting or lock inversion;
successor authority can precede first-record commit read-verification; torn
immutable headers can become authoritative; measured Flash latency violates
watchdog/network budgets; the selected backend cannot prove every torn commit
write fails the exact-pattern test; required program granularity/alignment or
repeated-program behavior is undocumented; the 734-byte limit cannot be
derived from public bounds; two erased sectors cannot be established before
successor creation; current state cannot survive every reclaim/reset cut; a
newest record cannot be selected unambiguously; or a proposal changes a v0.3.2
public contract. Do not assume page-program atomicity. Do not weaken the
guarantee or expand into Historical Event Access/general event persistence.
