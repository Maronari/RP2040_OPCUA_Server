# v0.6.0 T1 native signed-manifest verification

Date: 2026-10-31. Scope: native T1 only, following the
[frozen native contract](v0.6.0-t0-native-contract.md).

Hardware follow-up snapshot: `static/tests/ota_verifier_ram_probe/` adds an
opt-in RAM diagnostic using the real PSRAM allocator and measurement-only
crypto counters. The ELF has built with SRAM-only LOAD segments, but has not

is retained locally under the ignored `build/hardware/v060-t1/` directory.

## Implementation and bounds

`ota/include/ota/ota_verifier.h` and `ota/src/ota_verifier.c` provide manifest
authentication and exact-length streamed candidate verification. They validate
the fixed 320-byte format, canonical IDs/reserved bytes, SHA-256, raw low-S
ECDSA P-256 signatures, provisioned compatibility and version/content policy.
Outputs are cleared on failure. CRC remains a diagnostic only.

The application platform adapter owns a nonblocking operation mutex and one
65,536-byte PSRAM allocation, including the 4,096-byte stream buffer and private
allocator headers/payload. Missing PSRAM and exhausted memory reject verification;
there is no internal-SRAM fallback or image-sized allocation. All acquired memory
is wiped and released. No Flash writes or bootability decisions occur here.

`ota/cmake/verifier.cmake` compiles the vendored mbedTLS primitive closure with
a private configuration and generated symbol namespace. Live TLS retains its
existing configuration/FreeRTOS allocator. The application retains
`ota_verify_candidate` at link time to expose its actual static footprint before
T3 calls it. The bootloader platform adapter, persistent state and recovery layout
remain T2 work; service and OPC UA integration remain T3/T4 work.

`static/tools/test_ota_verifier.py` compiles the same native source and real
vendored crypto with strict host warnings and `-DNDEBUG`. Test signatures use
an ephemeral in-memory key; no signing private key is stored. The harness is
registered in the blocking host runner and checks private crypto symbol isolation.

## Verification limits

No signed firmware has been deployed. Production public keys/board revision,
protected signing infrastructure, hardware execution/timing, runtime PSRAM peaks
and stack watermarks remain unverified. Compiler `.su` files are per-function
static stack estimates, not measured call-chain peaks. The existing newlib
`_stat is not implemented` linker warning remains; it is not a first-party warning.

Public NodeIds, service signatures, configuration/persisted IDs and production
security defaults are unchanged. The unchanged public inventory was compared
against `2a0bcd8027b37e176e3264f739ee70cfb105e64b`.

The full host runner passed **94 suites**, including the new real-crypto suite
(`build/reports/v060-t1-host-tests.log`). Both cached Debug builds passed;
resolved configurations/toolchains remain in their CMake caches. Industrial
support remains **compile/mock validated, not hardware qualified**.
Blocking first-party cppcheck passed. Public inventory SHA-256 remains
`2f1bac21e15c468117b17e4b77385f49e133939346172b2c611e74bf1c736294`.

Static artifact reports were generated with `generate_static_size_report.py`,
using each build's ELF/map/UF2/BIN/cache and Arm GCC 13.3.1 `objdump`/`nm`.
The reports are `build/reports/v060-t1-static-size.json` and
`build/reports/v060-t1-industrial-static-size.json`; they retain sizes/hashes
separately from runtime measurements. Compiler stack-usage output is under
`build/ota/CMakeFiles/OTA_VERIFIER.dir/`.

The independent review requested a zero-key-ID format rejection and a valid
high-S malleation regression. Both were fixed, and unused private `platform.c`
was removed to eliminate unnamespaced platform globals. The focused native
suite and scoped cppcheck were rerun after these changes; the full 94-suite
run preceded these final fixes. Independent rereview found no actionable defects.

UaExpert run or hardware acceptance result is claimed.
