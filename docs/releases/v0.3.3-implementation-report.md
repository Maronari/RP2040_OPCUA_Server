# v0.3.3 implementation report

## Status

The `v0.3.3` Maintenance Journal and Condition Semantics implementation is
complete in the current working tree for the scoped build and documentation
milestone.

As of Wednesday, July 29, 2026, the implementation is not yet release-tagged.
`ROADMAP.md` still identifies `v0.3.3` as the first unreleased version.

The exact reference Debug configure/build succeeds for
`waveshare_core2350b_16mb_psram8mb` with `W5500`, and the single authoritative
firmware version source now reports `0.3.3` through runtime defines, OTA
metadata inputs, and generated configuration export.

## Scoped implementation outcome

This milestone closed the release-scoped build and documentation gaps around
the maintenance journal:

- removed a static archive order dependency by moving
  `maintenance_journal_codec.c` into `FIRMWARE_DRIVERS`, the target that owns
  `maintenance_journal_backend.c`;
- kept the required 360 KiB FreeRTOS heap and moved the 24576-byte maintenance
  export JSON scratch buffer from internal SRAM `.bss` into PSRAM;
- linked `OPCUA_DEVICE_MODEL` directly to `PSRAM_ALLOCATOR` so the new scratch
  dependency is explicit;
- documented the public maintenance method, NodeId, export, reset, and
  persistence contract;
- documented the journal schema, commit classification, recovery, retention,
  wear assumptions, diagnostics, export schema, and power-loss model;
- bumped the single authoritative firmware version source from `0.3.2` to
  `0.3.3`.

No broader build migration, dependency upgrade, or later-release
infrastructure was added in this milestone.

## Root cause and release-scoped fix

The initial exact Debug build reproduced two independent failures.

### 1. Static archive ownership / link-order failure

`maintenance_journal_backend.c` in `FIRMWARE_DRIVERS` referenced
`maintenance_journal_codec_*`, but the codec object was compiled only into
`services/libFIRMWARE_SERVICES.a`. The reference link response file showed the
driver archive being extracted before the final relevant services archive pass,
so resolution depended on archive order rather than target ownership.

Release-scoped fix:

- add `../services/src/maintenance_journal_codec.c` to `FIRMWARE_DRIVERS`
- remove `src/maintenance_journal_codec.c` from `FIRMWARE_SERVICES`

### 2. Internal SRAM overflow in the reference Debug build

With the required 360 KiB FreeRTOS heap restored, the linker overflow matched
the new `v0.3.3` maintenance export buffer. Symbol inspection showed
`g_model_maintenance_export_payload` consuming 24576 bytes of permanent
internal SRAM.

Release-scoped fix:

- change the export payload from a fixed `.bss` array to a PSRAM allocation
  owned by `opcua_model`
- fail closed if PSRAM is unavailable or the allocation fails
- free the allocation on `opcua_model_task()` shutdown
