# v0.4.0 — OPC UA Model Modularization

## Contract

Baseline: `v0.3.4`, commit `3ff4689e403fc806122cbafb509cc14cc4487bfb`.

Refactor `opcua_model` only. Preserve all externally visible behavior from the baseline.

No new NodeIds, BrowseNames, Methods, Events, companion specifications, configuration fields, channel-runtime changes, service features, persistence formats, or v0.4.1 work.

Use `code-mapper` first, `iot-engineer` for OPC UA implementation, `build-engineer` for CMake/size/verification, and `code-reviewer` after integration. The primary agent owns the final architecture and release gate.

## Implementation

Introduce internal `opcua_model_context_t` owning server handles, namespace indices, module state and bounded scratch storage.

Split `opcua_model.c` into focused modules covering at minimum:

* core/server lifecycle;
* channels;
* identity/DI/AMB;
* maintenance;
* configuration methods;
* security/audit;
* alarms/events;
* history;
* OTA;
* PubSub/MQTT;
* diagnostics.

Modules must communicate through explicit internal headers/context APIs, not source-order coupling or duplicated globals.

Centralize:

* public/internal NodeId definitions;
* namespace resolution;
* access-control mapping;
* browse-path helpers;
* event-field helpers.

Keep service APIs free of open62541 types where practical.

Keep the public `opcua_model.h` API compatible unless an internal-only extension is required.

Update CMake with explicit source lists. Feature-dependent modules may be disabled only by explicit existing/new CMake options; disabled modules must compile out cleanly.

Do not refactor service/driver internals unless required to remove an OPC-UA-layer dependency, and do not change their public behavior.

## Compatibility gate

Use `v0.3.4` as immutable compatibility baseline.

Before and after refactoring compare:

* exported public-node inventory/NodeSet;
* NodeIds and BrowseNames;
* Method signatures;
* EventTypes and custom fields;
* access-control behavior;
* config/security/OTA/history/AMB verification behavior.

Any unexplained public drift is a release blocker.

Existing verification scripts must continue to pass without semantic modification. Changes needed only for file/module locations are allowed; weakening assertions is forbidden.

## Size and architecture gate

Record baseline and final:

* `.text`, `.data`, `.bss`;
* ELF/UF2/BIN;
* persistent SRAM/PSRAM allocations;
* relevant task stacks.

This release is structural: no unexplained persistent RAM growth is allowed. Keep `.text` growth within 2% of the v0.3.4 reference build unless the final report identifies and justifies the exact cause.

No module may depend on another module merely because its `.c` file was initialized or compiled first. Shared state belongs in `opcua_model_context_t` or an explicit owner.

`opcua_model.c` must cease being the implementation monolith; if retained, it may contain only thin public entry points/core orchestration.

## Release gate

Run:

1. `git diff --check`;
2. all host tests;
3. first-party static analysis;
4. exact reference RP2350 Debug build;
5. existing config/security/OTA/history/AMB verification;
6. `verify_opcua_public_contract.py` against `v0.3.4`;
7. exported NodeSet/public inventory comparison;
8. artifact/version checks;
9. size comparison against `v0.3.4`;
10. independent `code-reviewer`.

Run affected asyncua/open62541 and UaExpert checks for the refactored OPC UA paths. Do not claim hardware/client verification that was not performed.

Fix failures and rerun affected gates. Do not stop after merely splitting files.

## Completion

Done only when:

* the monolithic model is decomposed into the required modules;
* module ownership/dependencies are explicit;
* all v0.3.4 public OPC UA behavior is preserved;
* existing verification passes;
* build and CI gates pass;
* size limits are satisfied or explicitly justified;
* no v0.4.1 feature entered the diff.

Do not modify `ROADMAP.md`, create a tag, or start the next release.

Final report must include changed modules, dependency structure, verification results, public-contract comparison, size delta and residual risks.
