# v0.5.2 T0 measurement contract

Status: frozen for implementation on 2026-09-16. This is the scoped T0
companion required by `docs/releases/v0.5.2.md`; it does not claim that T1-T6
or any hardware measurement has run.

The normative machine-readable contract is
`static/benchmarks/v0.5.2/measurement-contract.json`. Its validator is
`static/tools/validate_benchmark_contract.py`. The JSON contract version,
benchmark-profile version and result-report version are all `1` for v0.5.2.
Changing a meaning or removing a field requires a new version; additive
optional fields may retain the version.

## Measurement rules

- Every metric names its state. `unsupported`, `unavailable`, `exhausted`,
  `failed` and `not-run` are distinct and never encoded as a measured zero.
- Runtime resource values come from one-second coherent service snapshots.
  Build-layout values, runtime gauges, peaks, counters and task stack high-water
  marks remain separate. Internal SRAM, PSRAM and external Flash are never
  added into one undifferentiated total.
- Cumulative runtime counters are `UInt64` plus a same-owner wrap counter.
  Values wrap to zero; wrap counters saturate. They start at provider
  initialization and reset only at reboot unless the metric family explicitly
  states a shorter lifetime.
- Elapsed time uses monotonic clocks. Wall time is recorded only when valid.
  Event latency requires correlation and a valid device source timestamp;
  unrelated client/device wall clocks are never subtracted.
- Every distribution records population, p50, p95, p99 and maximum. A bounded
  sample store reaching capacity fails the run; it must not silently discard
  observations or reduce the declared load.
- The JSON bounds cap profiles, repetitions, warm-up, run duration, operation
  timeouts/retries, samples, pending correlations, continuation points,
  retained errors and report bytes. A bound violation is `exhausted` or
  `failed`, not a partial successful run.

## Source and synchronization map

The JSON `metricFamilies` array is the complete T0 inventory. The important
ownership boundaries are:

| Metrics | Authoritative owner | Publication rule |
|---|---|---|
| ELF/map, ELF/UF2/BIN and static SRAM/Flash | T1 build reporter | One build identity; missing/malformed inputs fail. Layout estimates are not runtime observations. |
| FreeRTOS heap and all-task state | `diag_service` using narrow FreeRTOS providers | One bounded double-buffered snapshot per second. No caller may compose several on-demand samples. |
| PSRAM top-level arena | `psram_allocator` provider consumed by `diag_service` | Mutex-coherent allocator snapshot; nested lwIP arena is not double-counted. |
| lwIP nested arena | `lwip_psram_heap` provider consumed by `diag_service` | Actual arena statistics or `BadNotSupported`; never infer usage from the PSRAM reservation. |
| OPC UA occupancy/rejection/event queue | T3 service state fed at definitive open62541 lifecycle sites | Mutations occur on `OpcUaTask`; audit-ring use is not subscription event-queue use. |
| Startup, session and operation latency | T5 client plus explicit device timestamps where needed | Client monotonic intervals; cold/warm setup recorded separately. |
| Sample interval and jitter | Native sampling hook | Device monotonic timestamps, at least two samples per distribution. |

The current implementation is not evidence for the new metrics: current heap
and PSRAM reads are on-demand, task registration covers only eight application
entries, the task sampler silently caps at 16, and unsupported PSRAM data may
appear as zero. T2 must replace those semantics without changing the legacy
NodeIds, BrowseNames, types or legacy stack-word units.

## Benchmark matrix

The final v0.5.2 matrix expands to 192 bounded cells:

- 1, 4, 8 or 16 synthetic channels;
- FULL Namespace 0;
- production Basic256Sha256/SignAndEncrypt or an explicit test-only security-off
  build profile;
- 1, 2 or 4 clients;
- 1 Hz or 10 Hz sample/subscription load;
- events off/on and history off/on.

REDUCED Namespace 0 is unsupported in v0.5.2: the bundled amalgamation is
generated with `UA_GENERATED_NAMESPACE_ZERO_FULL` and the repository has no
selector. This is a legitimate "where supported" exclusion, not a passed or
missing benchmark.

Only FULL + Basic256Sha256/SignAndEncrypt exists today. The security-off
variant remains T4 work and must never alter production defaults or production
artifacts. Likewise, T4 must create explicit synthetic configurations without
renumbering persisted preset IDs or changing `dev_benchmark`, which remains a
physical-input preset. The synthetic driver accepts source indices 0-7; a
16-channel profile may reuse source indices only after tests prove that each
channel's service-owned runtime context remains independent.

Profile IDs are deterministic and include every axis. Every cell must either
have reference-hardware evidence or an explicit `not-run` reason. Hosted CI
may verify builds, parsers and mocks but cannot manufacture heap, stack,
startup or latency measurements.

## Public-contract and resource effects

T0 adds no firmware code, public NodeId, BrowseName, method, configuration
field, persisted driver/preset ID, runtime buffer or task. Its runtime SRAM,
PSRAM, stack and external-Flash effect is zero. It adds only repository-hosted
JSON, documentation and host validation. T1-T6 must report their own measured
effects against released v0.5.1.
