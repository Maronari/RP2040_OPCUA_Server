# Модуль: `bootloader/`

## Назначение

Загрузчик второго этапа для RP2350: решает, какой образ прошивки
загружать, и — когда обновление OTA поставлено в очередь — копирует и
проверяет его из банка B в банк A до того, как приложение вообще начнёт
выполняться. Собирается только при `OTA_BUILD_BOOTLOADER=ON`. Полный
конечный автомат состояний и диаграммы см. в
[ota-bootloader.md](../ota-bootloader.md); эта страница — представление
на уровне справочника по модулю.

## Публичный API

Отсутствует — самостоятельный исполняемый файл (`ota_bootloader`), а не
библиотека.

## Внутренняя реализация

Точка входа `main()` ([bootloader/main.c:492](../../../bootloader/main.c)).
Последовательность: инициализация оборудования → чтение записи состояния
OTA → (если перезагрузка по сторожевому таймеру последовала за состоянием
`READY_TO_BOOT`) пометить запись как `FAILED` → (если ожидает применения
промежуточный образ) проверить + скопировать банк B → банк A, повторно
проверить, пометить `READY_TO_BOOT` или `FAILED` → (если `READY_TO_BOOT`)
увеличить `boot_attempts` → **решение о загрузке принимается исключительно
на основании валидации таблицы векторов банка A**, независимо от поля
`state` → переход к банку A, либо, если образ недействителен, оставаться
резидентно, бесконечно мигая светодиодом.

Ключевые внутренние функции: `bootloader_is_valid_bank_a_image()`
(`main.c:136-141`), `bootloader_record_pending_boot_failure()`
(`:342-355`), `bootloader_validate_staged_image()` (`:250-257`),
`bootloader_copy_bank_b_to_bank_a()` (`:273-321`),
`bootloader_prepare_ready_state_for_boot()` (`:323-340`),
`bootloader_jump_to_bank_a()` (`:465-490`),
`bootloader_quiesce_interrupt_sources()` (`:58-82`).

Загрузчик реализует **собственный** бесплатформенный (bare-metal) бэкенд
Flash (`main.c:200-210`, напрямую через `flash_safe_execute`), а не
использует общий `flash_operation_coordinator` — с каждым образом линкуется
ровно один бэкенд (`ota/src/ota_flash_backend.h:9-13`).

## Зависимости

`OTA_SHARED` (`ota/src/ota_flash.c` + `ota_state.c`), `pico_flash`,
`pico_multicore`, `hardware_flash`, `hardware_watchdog`. Использует
специфичный для загрузчика скрипт компоновщика, сгенерированный функцией
`ota_layout_set_bootloader_linker_script()`.

## Зависимые модули

Отсутствуют — это первое, что выполняется, ничто с ним не линкуется.

## Владение состоянием

Нет собственного персистентного состояния; читает и при необходимости
перезаписывает общую запись состояния OTA на устройстве
(`ota/include/ota/ota_state.h`) — см.
[persistence.md](../persistence.md#flash-region-map).

## Важные символы

См. таблицу в разделе «Внутренняя реализация» выше; все указанные
`path:line` относятся к `bootloader/main.c`.

## Контекст выполнения

Выполняется до появления FreeRTOS — однопоточно, прерывания в итоге
отключаются непосредственно перед переходом к приложению
(`bootloader_quiesce_interrupt_sources`).

## Синхронизация

Не требуется — однопоточное выполнение, отсутствует конкурентный доступ к
записи состояния OTA или банкам Flash.

## Аппаратные ресурсы

QSPI Flash (область загрузчика, банк A, банк B, область состояния OTA),
NVIC (маскируется перед передачей управления), SysTick (останавливается
перед передачей управления), встроенный светодиод (индикация мигания при
зависании).

## Персистентное состояние

Запись состояния OTA — единственная область Flash, в которую загрузчик
пишет напрямую (плюс банк A во время копирования). См.
[ota-bootloader.md](../ota-bootloader.md#flash-layout).

## Поведение при сбоях

**На сегодняшний день не существует резервного пути загрузки со
второстепенным образом.** Если таблица векторов банка A недействительна,
загрузчик останавливается и бесконечно мигает светодиодом. Если
скопированный образ структурно валиден, но функционально неисправен,
загрузчик будет продолжать попытки его загрузки (наращивая
`boot_attempts` без ограничения), поскольку в настоящее время ничто не
восстанавливает предыдущий заведомо исправный образ — полный анализ
пробела см. в
[ota-bootloader.md](../ota-bootloader.md#health-confirmation-and-rollback--current-gap)
(это задокументированная цель `v0.6.0`, пока не реализованная).
